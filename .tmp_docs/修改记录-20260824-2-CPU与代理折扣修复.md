  新增规则：

- `backend/app/Services/ProductCatalog/Concerns/HandlesProductCatalogHelpers.php`（`buildProductBatchUpdatePayload` 内，约 203-208 行）
  ```php
  foreach (['cpu_model', 'cpu_turbo'] as $cpuField) {
      if (array_key_exists($cpuField, $data)) {
          $cpuValue = trim((string) ($data[$cpuField] ?? ''));
          $update[$cpuField] = $cpuValue === '' ? null : $cpuValue;

  }
  ```
  - CPU 型号留空 = 清除（写 null）；睿频留空 = 不修改（仅填写时提交）——对齐前端语义。
- **`ProductCategoryService::batchUpdateGroupProducts` 解构 bug 修复**（约 282 行）：
  ```php
  // 原来（错误）：
  [, , $thirdGroupIds] = $this->collectCascadeDeleteScope($groupId, $level);
  // 修正为：
  [, $thirdGroupIds] = $this->collectCascadeDeleteScope($groupId, $level);
  ```
  `collectCascadeDeleteScope` 返回 `[productIds, thirdGroupIds, secondGroupIds, firstGroupId]`。原来取下标 2（secondGroupIds）导致批量更新 `requested_count=0` 不生效。此修复同时使「折扣分组 / 控制台类型」分组级批量更新恢复正常。

## 三、修复：CPU 配置不生效、管理端不回显

### 3.1 根因

批量设置的数据其实已写入 `products.cpu_model/cpu_turbo`（实测 2305-2310 均落库），但**读取链路多处商品查询的 `select` 没带这两列**：

- `ProductSiteService::resolveCpuModelPayload` 读 `$product->getAttribute('cpu_model')`，列不在 select 里时恒为 null → 回退目录绑定（为空）→ **www 选购页不显示配置的 CPU**；
- 管理端商品列表/详情资源未输出这两列 → **管理端不回显**。

### 3.2 后端 select 补齐（4 处）

- `backend/app/Services/ProductCatalog/ProductV2QueryService.php`
  - `siteProductListColumns`（www 商品列表，同时被 siteProductDetailColumns 复用）`optionalSelectColumns` 增加 `'cpu_model', 'cpu_turbo'`；
  - `adminProductDetailColumns`（admin 商品详情）增加 `'cpu_model', 'cpu_turbo'`。
- `backend/app/Services/ProductCatalog/ProductGroupV2QueryService.php`
  - `paginateSiteProducts`（`/v2/site/product-groups/{group}/products`）select 追加 `...Product::optionalSelectColumns(['cpu_model', 'cpu_turbo'])`。
- `backend/app/Services/ProductCatalog/ProductAdminService.php`
  - `adminProductList` 的 `optionalSelectColumns` 增加 `'cpu_model', 'cpu_turbo'`。
- `backend/app/Services/ProductCatalog/ProductSiteService.php`
  - `catalogProductsByGroupIds` 与 `findSaleProductForDetail` 的 select 增加 `'cpu_model', 'cpu_turbo'`（该处原本已带，保持一致）。

### 3.3 资源输出（2 个）

- `backend/app/Http/Resources/Admin/V2/AdminProductSummaryResource.php`：新增 `cpu_model`、`cpu_turbo` 输出。
- `backend/app/Http/Resources/Admin/V2/AdminProductDetailResource.php`：`configuration` 段新增 `cpu_model`、`cpu_turbo`。

### 3.4 商品细粒度配置保存链路（新建/编辑商品）

- `backend/app/Http/Requests/Admin/V2/Product/StoreProductRequest.php`（`UpdateProductRequest` 继承）：新增
  ```php
  'cpu_model' => ['nullable', 'string', 'max:120'],
  'cpu_turbo' => ['nullable', 'string', 'max:40'],
  ```
- `ProductAdminService::prepareProductPayload` 的 `base`：按 `array_key_exists` 条件写入：
  ```php
  ...(array_key_exists('cpu_model', $data) ? ['cpu_model' => $this->normalizeNullableString($data['cpu_model'] ?? null)] : []),
  ...(array_key_exists('cpu_turbo', $data) ? ['cpu_turbo' => $this->normalizeNullableString($data['cpu_turbo'] ?? null)] : []),
  ```
  缺省不覆盖，避免普通编辑把已配置的 CPU 清掉。

### 3.5 admin 管理端回显（前端）

`frontend-admin-v3/src/pages/products/components/ProductCatalog.vue`
- 商品表格新增「CPU 型号」列（`colKey: 'cpu'`，宽 180）：显示 `row.cpu_model` + 次要行 `row.cpu_turbo`；
- 「CPU 规格」批量弹窗打开时**自动预填当前值**：所选商品（或分组下商品，经 `productApi.list({ ...productGroupPayload(group), page_size: 100 })` 拉取）的 CPU 型号/睿频一致时回填，不一致留空；
- 新增 `resolveBatchTargetProductRows(targetRows, group)` 辅助函数（已选商品直接返回，否则按分组拉取列表）；
- `frontend-admin-v3/src/pages/products/index.less`：`.product-cpu-cell` / `__model` / `__turbo` 样式。

## 四、修复：代理折扣全链路

> 用户反馈：用户控制台代理等级不展示；购买产品没有代理折扣；批量设置的折扣分组"没设置到每个产品"。

### 4.1 排查结论

| 现象 | 根因 |
|---|---|
| 用户控制台代理等级不展示 | **没有任何用户绑定代理组**（库表 `users.agent_group_id` 全为空）；且绑定链路三处坏死（见 4.2） |
| 购买产品没有代理折扣 | 报价查询 `findSaleProductForQuote` 的 select **缺 `product_discount_group_id`** → 报价时永远解析不到商品折扣组 → 恒 100%（见 4.3） |
| 批量折扣分组"没设置到每个产品" | 批量写入实际成功（实测 6/6），但管理端商品列表不回显折扣分组，无法验证（见 4.4） |

### 4.2 用户绑定代理组链路修复（后端 3 处坏死）

`backend/app/Services/User/UserService.php`
- **缺 `use App\Models\AgentGroup;`** → `resolveAgentGroupId()` 里 `AgentGroup::query()` 解析成 `App\Services\User\AgentGroup`，绑定必然抛 "Class not found"。已补 import。
- `update()` 里 `collect($data)->only([...])` 列表**缺 `agent_group_id`** → 即便传入也被过滤。已补。

`backend/app/Http/Requests/Admin/V2/User/UpdateUserRequest.php`
- `rules()` **缺 `agent_group_id` 校验规则** → `safe()->only(['agent_group_id'])` 拿不到该字段，永远保存不进去。已补：
  ```php
  'agent_group_id' => ['nullable', 'integer', 'exists:agent_groups,id'],
  ```

管理端用户页新增绑定入口：
- `frontend-admin-v3/src/pages/users/index.vue`
  - 表格新增「操作」列（宽 120，fixed right），行内「绑定代理」按钮（`canManageUsers` 权限）；
  - 新增「绑定代理组」弹窗：说明文案 + 代理组 `t-select`（clearable，数据源 `agentGroupsApi.list()`，清空 = 解除代理归属）；
  - `openAgentGroupDialog(row)` 回填当前 `agent_group_id`；`handleAgentGroupSave()` 调 `userApi.update(id, { agent_group_id })`，成功后刷新列表；
  - 新增 import：`AgentGroupRecord`、`agentGroupsApi`、`errorMessage`（来自 `@/utils/userMessage`）。
- `frontend-admin-v3/src/pages/users/index.less`：`.users-agent-group-desc` 样式。

> 绑定后：管理端用户列表/详情显示代理组；用户控制台「个人中心 → 账户资料」已有「代理组」项（`agentGroup?.name`），数据到位即展示；官网选购与续费按矩阵应用代理折扣。

### 4.3 购买无折扣修复（报价链路）

`backend/app/Services/Site/SiteProductQuoteService.php`
- `findSaleProductForQuote` 的 select **补 `'product_discount_group_id'`**（原来缺列 → `productDiscountGroup` 关系匹配不上 → `AgentDiscountService` 返回空折扣）。

> 建单链路（`CheckoutService`，`Product::query()->lockForUpdate()->findOrFail`）与续费链路（`resolveEffectiveProduct`，`Product::query()->find`）均为全列查询，本就可用，无需改。

实测（tinker，商品 2305 折扣组 9 + A1代理 矩阵 85%）：
```
total_amount=42.50  original_total_amount=50.00  agent_discount_rate=85.00
agent_discount_amount=7.50  agent_amount=42.50  agent_group_name=A1代理
```

### 4.4 商品折扣分组管理端回显

后端：
- `ProductAdminService::adminProductList` select 补 `'product_discount_group_id'`，`with` 增加 `'productDiscountGroup'`；
- `ProductV2QueryService::adminProductDetailColumns` select 补 `'product_discount_group_id'`，`findAdminProduct` 的 `with` 增加 `'productDiscountGroup'`；
- `AdminProductSummaryResource` 新增 `product_discount_group_id` / `product_discount_group_name` / `product_discount_group_min_discount_rate`；
- `AdminProductDetailResource` 的 `configuration` 段新增同名字段（无 name 段）。

前端（`ProductCatalog.vue`）：
- 商品表格新增「折扣分组」列（`colKey: 'discountGroup'`，宽 140）：有分组显示 t-tag 分组名，无则「未分组」；
- 「折扣分组」批量弹窗打开时**自动预填当前分组**（所选商品/分组下商品折扣分组一致时回填该 id，否则留空）。

# 上游供應商對接

機器從上游開出來，前提是供應商記錄、憑據與商品綁定三樣都配好。本文説明入口、三種供應商協議怎麼選、憑據填什麼、連通性怎麼自檢，以及開通失敗時先看哪裡。

## 1. 後台入口

| 頁面          | 路徑                                | 權限                                                                                                  |
| ------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 上游提供商    | 產品配置 → 上游供應 → 上游提供商    | `supplier.list` / `supplier.detail`                                                                   |
| 上游開通插件  | 系統設置 → 集成插件 → 上游開通      | 列表 `integration_plugin.view`；安裝/啟停 `integration_plugin.manage`；測試 `integration_plugin.test` |
| 商品管理      | 產品配置 → 商品管理 → 商品管理      | `product.list` / `product.manage`                                                                     |
| 服務實例      | 服務管理 → 服務實例                 | 服務相關權限                                                                                          |
| 上傳/清理日誌 | 日誌中心 → 日誌管理 → 上傳/清理日誌 | `log.list`                                                                                            |

`supplier.manage` 才能新增/修改/刪除供應商，`supplier.sync` 才能跑同步任務與批量對接，`supplier.secret_reveal` 才能明文查看已保存的憑據（10 次/分鐘限流並寫操作日誌）。

## 2. 可用的上游協議

供應商表單的字段**由提供商類型決定**，不是每個類型都一樣。當前可選項：

| 提供商類型       | provider_key        | 憑據字段                                                                                 | 協議説明                                                    |
| ---------------- | ------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 主機面板接口     | `hosting_panel_api` | `api_url` 接口地址、`api_username` 接口賬號、`api_key` 接口密鑰                          | 通用主機面板協議，核心內置，不需要裝插件                    |
| ZJMF 財務接口    | `zjmf_finance_api`  | 同樣走上面三項憑據（該插件不聲明自定義表單字段）                                         | 對接魔方財務上游，需啟用 `zjmf_finance` 插件                |
| 康樂虛擬主機     | `kanghostx`         | 接口地址填面板根地址，API 密鑰填 accesshash                                              | Kangle WHM API，需啟用 `kanghostx` 插件                     |
| TuraIDC 開放接口 | `tura_open_api`     | 接口地址填上游站點根地址，API 密鑰填上游「API 密鑰」頁創建的完整密鑰（僅創建時展示一次） | 純自有協議，不走 ZJMF 兼容鏈路，需啟用 `tura_open_api` 插件 |
| Demo 上游服務    | `demo_servers`      | 無真實憑據，只模擬上游                                                                   | 僅用於驗證流程                                              |

供貨商類型下拉框的候選來自「插件註冊表 + 核心驅動」，未安裝的插件不會出現在下拉里；選了卻保存不了會報參數校驗錯誤。選不到某個類型時先去「上游開通」插件頁安裝並啟用它。

`hosting_panel_api`（主機面板接口）是內置驅動，但下拉框走的是插件註冊表，需要有對應的上游插件記錄才會出現。如果你確認代碼裡有這個驅動、下拉里卻沒有，先在「上游開通」頁點「掃描插件」；仍然沒有説明該驅動在當前部署裡沒有可註冊的插件條目（具體註冊方式未在代碼中確認）。

`zjmf_finance` 插件的配置頁只有一個只讀的「上游標識」`zjmf_finance_api`，並明確要求供應商綁定的 `provider_key` 保持該值、不要別名為 `hosting_panel_api`——填成別名會導致走錯適配鏈路。

`tura_open_api` 要求上游密鑰具備 `products/orders/services/finance` 讀寫權限且上游賬戶餘額充足；密鑰只在上游創建時展示一次，丟了只能重建。

## 3. 新增供應商

1. 「上游提供商」頁點「添加提供商」，先選「插件提供商」（即上面的提供商類型）。
2. 「接口名稱」是隻在本站顯示的供應商名字。
3. 按選中的類型出現對應憑據字段：必填項留空無法保存；已保存過的密鑰字段會顯示「已配置」，編輯時留空表示**保持原值**而不是清空。
4. 「上游餘額告警」區：`low_balance_alert_enabled` 開關與 `low_balance_threshold` 閾值。閾值留空表示沿用默認值 20，**不等於**關閉提醒。
5. 保存後供應商以啟用狀態（`status=1`）存在；用它行內的啟用/停用按鈕切換，停用不會影響已開通的服務，但新的開通不會走它。

接口地址有嚴格校驗：必須是 `http` 或 `https` 且帶主機名，**非 local 環境強制 HTTPS**，禁止帶賬號密碼，禁止 `localhost` 與 `.localhost` 結尾的域名，禁止內網與保留 IP。另外可以用 `HOSTING_PANEL_API_ALLOWED_HOSTS`（逗號分隔）把允許的域名收緊成白名單，一旦設置，不在名單內的域名會被拒。

憑據存儲的實質是 `supplier_plugin_bindings` 行：`base_url`、`account_name`、API 密鑰，加上插件自定義的 `provider_config`。同一供應商下可能有多條綁定（例如同時對接兩個不同的上游），「批量導入/對接」裡指定的 `supplier_id` + 來源組合就是用來區分它們的。

## 4. 商品怎麼連到上游

憑據配好不等於能賣，還要把本地商品與上游商品綁上：

- 打開商品編輯頁，在供應商下拉里選這個供應商，再同步或選擇上游商品；選擇時會實時拉取上游商品列表，拉不到就説明憑據或網絡有問題。
- 或者在「上游提供商」頁用供應商卡片上的「批量導入/對接」：先刷新上游商品樹，勾選要對接的遠端商品與本地的目標分類，再執行。對話框裡有三個選項：「默認上架」「自動開通」「同步配置項」，分別決定導入後的商品狀態、是否走自動開通、是否把上游的配置項模板一併帶過來。
- 上游商品的配置項模板可以按單個商品查看（卡片動作裡的 `config-template`），用於核對參數是否齊全。

批量對接需要 `supplier.sync`；沒有該權限時按鈕點了只會提示，不會靜默失敗。

## 5. 自檢與驗證

按順序檢查，每一步都能定位到一層：

1. 上游開通插件頁的「檢測」（`health_check`）：校驗清單與必需配置、實例化入口類，回答「插件能不能正常加載」；不聯繫上游。
2. 上游開通插件頁的「連接測試」：解析插件聲明的第一個能力，驗證插件在運行時能取到。
3. 供應商卡片上的「同步餘額」：真正請求上游並刷新「上游餘額 / 最近更新時間」。餘額一直是 `-` 且按鈕灰着（提示「接口配置不完整，暫時無法同步餘額」），説明 `api_url`、`api_username`、`api_key` 有缺失。
4. 供應商卡片上的「批量導入/對接」：能拉到上游商品樹，説明憑據、HTTPS、域名白名單與網絡全部打通。
5. 用一筆真實小額訂單走開通，然後到「服務實例」看狀態，到「上傳/清理日誌」「工單推送日誌」看上游交互記錄。

```bash
# 后端到上游的网络连通性：上游调用不做 SSL 校验，但网络与域名白名单仍会挡住请求
curl -sS -o /dev/null -w '%{http_code}\n' --max-time 10 https://你的上游域名/
```

上面這條只是確認網絡可達，真正的接口鑑權要看第 3、4 步的結果。

## 6. 排障

- **下拉里沒有想要的提供商類型**：對應插件沒安裝或沒啟用，先去「上游開通」插件頁處理。
- **保存報「上游接口地址必須使用 HTTPS」**：非 local 環境強制 HTTPS，純 HTTP 上游要麼改域名證書，要麼在本地聯調環境驗證。
- **報「上游接口域名不在允許範圍內」**：`HOSTING_PANEL_API_ALLOWED_HOSTS` 設了白名單，把上游域名加進去或清空該變量。
- **餘額同步失敗**：先看是網絡、域名白名單還是憑據問題——錯誤信息由 `ProviderErrorMapper` 統一成中文，會寫明是「接口暫時不可用」還是業務錯誤。
- **訂單支付了但機器沒開出來**：新購與續費在支付回調裡同步履約，同步失敗才回退 `provision` 隊列由每分鐘心跳重試。先看服務實例的最近一次開通嘗試記錄，再看隊列是否在跑（見[部署與調度](../deploy/scheduling.md)）。
- **供應商停用後老服務受影響嗎**：停用隻影響後續開通路由，已開通服務仍可管理；但狀態同步類定時任務不會再從它拉數據。

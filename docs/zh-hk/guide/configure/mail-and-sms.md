# 郵件與短信

郵件與短信都走「集成插件」：先在插件頁安裝並啟用一個通道插件，再填憑據，最後打開站點設置裡的通知總開關。三個環節少一個，對外就發不出驗證碼。本文按這個順序説明入口、字段、留空後果與驗證方法。

## 1. 後台入口

| 頁面                 | 路徑                                          | 權限                                        |
| -------------------- | --------------------------------------------- | ------------------------------------------- |
| 郵件發送（插件列表） | 系統設置 → 集成插件 → 郵件發送                | 列表 `integration_plugin.view`；安裝/改配置/啟停 `integration_plugin.manage`；測試發送 `integration_plugin.test` |
| 短信發送（插件列表） | 系統設置 → 集成插件 → 短信發送                | 同上                                        |
| 通知總開關           | 站點內容 → 站點配置 → 站點設置 → 通知總開關   | 頁面 `site.view`，寫入 `settings.manage`    |
| 郵件模板             | 站點內容 → 通知與接口 → 郵件模板              | `settings.view` / `settings.manage`         |
| 短信模板             | 站點內容 → 通知與接口 → 短信模板              | 同上                                        |
| 郵件日誌 / 短信日誌  | 日誌中心 → 日誌管理 → 郵件日誌 / 短信日誌     | `log.list`                                  |

插件列表頁會掃描 `backend/plugins/{domain}/` 下的目錄，本地新增插件文件後點「掃描插件」才會出現。安裝與啟用是兩步：點「安裝」寫入記錄，再點「啟用」激活運行時。

「發送測試郵件 / 發送測試短信」屬於測試接口（`integration_plugin.test`），限流 10 次/分鐘——它會真實發信，只是走了直髮通道。沒有這個權限的賬號在插件詳情頁點測試會提示無權限。

## 2. 一個功能域只能啟用一個插件

`mail`、`sms` 與 `captcha`、`verification` 同屬「單啟用域」。域內已有一個啟用插件時再去啟用第二個，會直接報「當前功能域已啟用「XXX」，請先停用後再啟用其他插件」（錯誤碼 42200）。支付與上游不受此限制，可以並存多個。

啟用的同時會寫一條驅動綁定記錄，系統按它決定當前用哪個驅動；綁定找不到時才回退環境變量 `MAIL_DRIVER_DEFAULT`（默認 `smtp`）與 `SMS_PROVIDER_DEFAULT`（默認 `aliyun`）。所以換短信服務商的標準做法是：先停用舊插件，再啟用新插件，不需要改 `.env`。

## 3. 郵件通道

可選插件：`smtp`（Single SMTP，生產用這個）、`multi_smtp_round_robin`（多 SMTP 輪詢）、`demo_mail`（演示，不連接真實 SMTP）。

`smtp` 插件字段：

| 字段                    | 默認值 | 留空後果                                       |
| ----------------------- | ------ | ---------------------------------------------- |
| `host` SMTP 主機        | 空     | 發送直接拋「郵件接口配置不完整」               |
| `port` SMTP 端口        | `465`  | 端口 ≤ 0 同樣報配置不完整                      |
| `username` SMTP 賬號    | 空     | 報配置不完整；同時兼作默認發件人地址           |
| `password` SMTP 密碼    | 空     | 報配置不完整（保存後不回顯，留空保存表示不改） |
| `from_address` 發件人地址 | 空   | 回退使用 SMTP 賬號，保持老配置行為             |
| `from_name` 發件名稱    | 空     | 回退當前站點名稱                               |
| `encryption` 加密方式   | 「自動」 | 自動時按端口推斷：465 → SSL，25 → 無，其餘 → TLS |
| `timeout_seconds` 超時秒數 | `8` | 無效值同樣按 8 秒處理                          |
| `rate_limit_enabled` 啟用電郵驗證碼限流 | 開 | 關閉後單 IP 不再限制驗證碼請求            |
| `ip_minute_limit` 單 IP 每分鐘上限 | `6` | 填 0 表示不限制                         |

`from_address` 與 SMTP 賬號可以不同；多數企業電郵要求兩者一致或已授權，不一致會被對方拒收，這屬於對端策略，系統不做校驗。

`multi_smtp_round_robin` 用「SMTP 賬號列表」（`accounts`，JSON 類型、標記為密鑰）維護多個賬號，通過賬號管理器維護，失敗後自動輪詢到下一個可用賬號，`cooldown_seconds` 默認 60 秒，即發送失敗的賬號冷卻 60 秒後才重新參與輪詢。它的限流項與 `smtp` 相同。

郵件模板在「郵件模板」頁維護，落到 `notification_templates` 表，鍵名前綴為 `email_template_subject_`、`email_template_content_`、`email_template_enabled_`。在後台改過內容或啟用開關的模板會被標記為已個性化（`is_custom=1`），系統升級時**不會**用新版默認模板覆蓋它；沒動過的模板會隨升級刷新。升級後覺得某封郵件樣式沒更新，先看這個模板是不是被改過。

## 4. 短信通道

可選插件四個，能力並不相同：

| 插件 slug    | 名稱             | 上游產品與接口                                    |
| ------------ | ---------------- | ------------------------------------------------- |
| `aliyun`     | 阿里雲號碼認證   | 號碼認證（PNVS）/ `SendSmsVerifyCode`，免資質，僅中國大陸號碼 |
| `aliyun_sms` | 阿里雲短信服務   | 短信服務（SMS）/ `SendSms`，V3 簽名，需資質報備與簽名、模板審核 |
| `stay33`     | MC雲短信         | 按平台 API 信息填用戶名與用戶密鑰                 |
| `demo_sms`   | Demo 短信        | 只模擬發送結果，用於驗證插件流程                  |

`aliyun` 與 `aliyun_sms` 是阿里雲的兩個獨立產品，控制台、接口、套餐包、簽名與模板體系互不相通，模板不能互換。`aliyun` 的驗證碼模板由插件按業務場景內置選擇（控制台贈送的 100001–100005），因此**沒有模板 ID 填寫項**；用錯產品會出現「扣了號碼認證套餐但短信服務的模板報缺參數」這類錯配。

`aliyun_sms` 字段較多，分四組：

- 憑據：`access_key`、`secret_key`（AccessKey Secret）、`sign_name`（短信簽名，必須是控制台「簽名管理」中審核通過的名稱）、`endpoint`（默認 `dysmsapi.aliyuncs.com`，僅專屬/國際站接入點才需要改）。
- 驗證碼模板：`template_code` 默認模板 ID（必填，形如 `SMS_123456789`，所有場景都回退到它）；`code_variable` 驗證碼變量名（默認 `code`，必須與模板正文的 `${...}` 佔位符一致）；`expire_variable` 有效期變量名（留空表示模板裡沒有該變量，填了但模板沒有會被阿里雲拒絕）。
- 分場景模板：`template_login`、`template_change_phone`、`template_reset_password`、`template_bind_phone`、`template_verify_bound_phone`，全部可留空，留空即沿用默認模板。只備案了一個模板時只填默認模板即可。
- 限流與高級：`rate_limit_enabled`（默認開）、`ip_minute_limit`（默認 `6`，0 表示不限）、`request_timeout`（默認 10 秒，範圍 3–30）。

`code_variable` 填錯是最常見的一類故障：阿里雲會返回「模板參數缺失」，日誌裡能看到，但短信就是發不出去。

`stay33` 需要 `username`、`api_key`（用戶密鑰）、`sign_name`（簽名名稱，不含外層 `【】`），發送前需在平台完成簽名與實名並確認賬號有額度。

## 5. 短信模板

「短信發送」插件裡的模板 ID 是通道側的編號；系統側每個通知場景還有自己的模板記錄，在「短信模板」頁維護，落到 `notification_templates` 表。對應設置鍵為 `sms_template_content_{code}`、`sms_template_provider_template_id_{code}`、`sms_template_enabled_{code}`。

`provider_template_id` 是「這個系統場景用通道的哪個模板」的映射，解析順序是：本次調用顯式傳入 → 模板行上存的 `provider_template_id` → 舊版驗證碼模板 ID → 回退用系統模板編號本身。所以只配 `aliyun_sms` 的默認模板、其餘留空也能跑通驗證碼；要用不同場景發不同短信，才需要逐個場景指定通道模板 ID。

## 6. 驗證與排障

按下面順序驗證，每一步都能定位到具體環節：

1. 插件詳情頁點「檢測」（`health_check`）：校驗清單文件、必需的配置項是否齊全，並實例化入口類；入口類自己實現了健康檢查時還會返回它的結果。它**不聯繫上游、不發信**，只回答「這個插件能不能正常加載」。
2. 阿里雲短信服務插件配置裡的「檢測」按鈕：一次性只讀核驗憑據、簽名與模板，並比對模板正文的變量名，不發短信、不計費。簽名或模板沒審核通過會在這裡暴露。
3. 郵件插件詳情頁「發送測試郵件」（填收件人電郵，固定用賬號索引 0）或短信插件詳情頁「發送測試短信」（填手機號）。這一步走驅動直髮，**繞過通知總開關**；如果總開關是關的，成功提示裡會明確寫出「但站點設置中的『啟用郵件通知』當前為關閉狀態，對外仍不會發送郵件」，不要把它讀成「已經能用了」。
4. 打開站點設置裡的 `email_enabled` / `sms_enabled`。
5. 用真實用戶走一遍註冊或找回密碼，然後到「郵件日誌」或「短信日誌」看記錄：日誌裡帶收件人、模板編號、通道模板 ID、狀態與錯誤信息，失敗原因就在這裡。

```bash
# 出问题时先确认队列与调度在跑，通知类任务由心跳驱动
cd /你的项目/backend
php artisan schedule:run
```

常見故障對照：

- 測試成功但用戶收不到：通知總開關是關的，或對應模板被停用（`is_enabled` 為 0）。
- 短信報「模板參數缺失」：`code_variable` 與通道模板正文的變量名不一致。
- 報「短信驅動 [xxx] 未註冊」：啟用了插件但沒有綁定記錄，重新停用再啟用一次。
- 郵件報「郵件接口配置不完整」：`host`、`port`、`username`、`password` 有一項為空。

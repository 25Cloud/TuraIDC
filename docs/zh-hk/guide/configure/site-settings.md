# 站點與品牌設置

站名、Logo、主題色這些三端都可見的信息統一在管理端一個頁面維護，保存後寫入 `settings` 表並即時下發。本文説明每一項填什麼、留空會怎樣、改完怎麼驗證。

## 1. 後台入口

| 頁面                 | 路徑                              | 頁面權限    | 讀寫接口權限                             |
| -------------------- | --------------------------------- | ----------- | ---------------------------------------- |
| 站點設置（基礎信息） | 站點內容 → 站點配置 → 站點設置    | `site.view` | 讀 `settings.view`，寫 `settings.manage` |
| 通知總開關           | 同上頁面「通知總開關」分區        | `site.view` | 同上                                     |
| 首頁 Banner          | 站點內容 → 站點配置 → 首頁 Banner | `site.view` | 同上（首頁裝修走自己的接口）             |

站點設置頁面的可見性看 `site.view`，但表單讀的是 `GET /api/v2/admin/settings`、寫的是 `POST /api/v2/admin/settings`，這兩個接口分別要求 `settings.view` 與 `settings.manage`。只給了 `site.view` 的賬號能進頁面、點了保存會提示無權限——這不是頁面故障，是權限沒配全。系統裡定義了 `site.manage` 這個權限常量，但當前沒有任何路由使用它（未在代碼中確認它的用途）。

## 2. 基礎信息字段

配置分組是 `basic`，鍵名即下面每項的行內代碼。

| 字段                                         | 默認值                                | 生效範圍                               |
| -------------------------------------------- | ------------------------------------- | -------------------------------------- |
| `site_name` 站點名稱                         | `图拉云`                              | 官網、用戶控制台、管理端、郵件         |
| `browser_title` 瀏覽器標題                   | 空（回退站點名稱）                    | 官網首屏、標籤頁、分享卡片             |
| `site_logo` 站點 Logo                        | 空（回退 `/branding/logo.png`）       | 官網、控制台導航                       |
| `site_favicon` 站點 Favicon                  | 空（回退 `/branding/favicon-32.png`） | 瀏覽器標籤頁圖標                       |
| `client_console_icon` 用戶控制台圖標         | 空（回退 Favicon）                    | 控制台側邊欄、登錄頁                   |
| `brand_primary_color` 品牌主色               | `#165DFF`（TDesign 品牌藍）           | 三端強調色                             |
| `brand_radius` 界面圓角                      | `6`                                   | 三端控件與容器圓角                     |
| `product_display_mode` 商品展示方式          | `list`（列表式）                      | 前台商品列表默認形態（訪客可自行切換） |
| `service_phone` 官方 QQ 羣                   | 空（回退文案「待補充羣號」）          | 官網頁腳、控制台聯繫方式               |
| `service_email` 合作電郵                     | 空（該行不顯示）                      | 官網頁腳、控制台聯繫方式               |
| `service_hours` 服務時間                     | 空（該行不顯示）                      | 官網頁腳、「關於我們」頁               |
| `support_group_qr` 官方羣聊二維碼            | 空                                    | 官網與控制台的聯繫入口                 |
| `support_group_link` 入羣鏈接                | 空                                    | 同上                                   |
| `icp_record` ICP 備案號                      | 空（頁腳該行不顯示）                  | 官網頁腳                               |
| `value_added_license` 增值電信業務經營許可證 | 空                                    | 官網頁腳                               |
| `terms_url` 服務條款鏈接                     | 空                                    | 註冊與下單頁的服務條款入口             |
| `privacy_url` 隱私政策鏈接                   | 空                                    | 同上                                   |

品牌主色與圓角的取值有硬校驗，填錯不是「不好看」而是「靜默回退默認值」：

- `brand_primary_color` 只接受 `#RRGGBB` 或 `#RGB`，三位寫法會展開成六位並轉小寫。帶分號、花括號、逗號或 `url()` 的輸入會讓整條樣式規則失效甚至成為注入點，系統直接回退 `#165DFF`。管理端表單本身也有 `#(?:[0-9a-fA-F]{3}|[0-9a-fA-F]{6})` 的正則校驗，但服務端不信任前端，落庫前會再校驗一次。
- `brand_radius` 只接受 0–24 的整數像素，超過 24 回退 `6`。項目規範是容器取該值、控件取一半，即默認的 6px / 3px；填成 30 這類值會看到圓角忽然變小，那是回退，不是沒保存。
- `service_qq_group` 與 `service_phone` 是同一展示位的兩個候選鍵，取值時先看 `service_qq_group`，為空再取 `service_phone`，都為空則顯示佔位文案「待補充羣號」。官網頁腳上那一行寫着「待補充羣號」就説明這裡沒填。

`client_console_icon` 只在用戶控制台生效；官網頂欄與頁腳用的是站點 Logo 加站點名稱。圖片字段接受的是媒體庫上傳後的地址，也可以直接填 `/branding/` 下的靜態文件名。

`product_display_mode` 只決定訪客**第一次**打開選購頁看到的形態。訪客可以在選購頁右上角切換「卡片式 / 列表式」（手機端同樣有切換條），還可以在「頁面寬度」面板裡選固定寬度（1200 / 1280 / 1440 / 1600 / 1920）或撐滿屏幕；兩項偏好分別記在該瀏覽器的 `localStorage`（`turaidc:shop-display-mode`、`turaidc:shop-page-width`）裡，換瀏覽器、換設備或清快取後回到站點默認值。想確認站點默認值實際生效，請用無痕窗口打開選購頁，或先清掉這兩個鍵。

## 3. 通知總開關

同一頁面「通知總開關」分區屬於 `notification` 分組：

- `email_enabled` 啟用郵件通知，默認關閉。
- `sms_enabled` 啟用短信通知，默認關閉。

這兩個開關是「對外是否真的會發信」的唯一判定源。關閉時註冊驗證碼、找回密碼等對外發碼會直接返回「郵件服務暫不可用」，而管理端插件詳情頁的「發送測試郵件 / 發送測試短信」按鈕走驅動直髮、不受總開關約束——測試成功不代表對外可用，測試結果裡會額外回傳總開關狀態並提示這一點。通道本身的配置見[郵件與短信](mail-and-sms.md)。

## 4. 保存後多久生效

- 讀取接口 `GET /api/v2/site/config` 不快取，刷新官網或控制台即可看到新站名。
- 保存 `basic` 分組會觸發內容版本號自增，官網的 SEO 渲染結果與 sitemap 快取立即失效，不需要等 TTL 過期，也不用手動清快取。
- 瀏覽器標籤頁圖標與標題由首屏腳本按上次訪問留下的 `localStorage` 快取先渲染一次，再被接口結果覆蓋。**同一個標籤頁裡改名不會立刻改標題**，新開標籤頁就正常。
- 官網上靜態引用的圖片（例如直接寫在 Nginx 裡的 favicon）可能被 CDN 或瀏覽器快取，這部分策略見[前端站點 Nginx 規則](../maintain/nginx-rules.md)。

## 5. 驗證

用接口確認服務端的真實取值，不要只看頁面回顯（頁面回顯帶表單本地狀態）：

```bash
curl -s https://你的官网域名/api/v2/site/config | head -c 800
```

返回裡的 `site_name`、`browser_title`、`site_logo`、`site_favicon`、`brand_primary_color`、`brand_radius` 就是三端實際使用的值。隨後逐項人工確認：

1. 新開瀏覽器標籤頁打開官網，標籤頁標題與圖標已是新品牌。
2. 刷新官網首頁與用戶控制台，站點名與主色已變；管理端刷新後主色同步。
3. 官網頁腳的備案號、服務時間、合作電郵按填寫內容顯示，留空的整行不出現。
4. 用無痕窗口打開選購頁，商品列表按 `product_display_mode` 的取值呈現為列表式或卡片式；普通窗口裡訪客的切換偏好會覆蓋默認值，這是預期行為。

改完沒有任何變化時，按順序排查：賬號是否有 `settings.manage`（保存本身被拒）、`brand_primary_color` / `brand_radius` 是否被服務端校驗回退、瀏覽器是否拿着舊的標籤頁快取。

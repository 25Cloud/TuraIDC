# 商品與計費

商品是本站對外銷售的配置單元：在這裡決定賣什麼、賣多少錢、庫存多少、是否自動開通。本文按「先建分組、再建商品、最後定價格與庫存」的順序講，最後給出驗證清單。所有結論來自當前代碼實現，涉及字段的默認值與校驗以代碼為準。

## 1. 配置順序

1. **商品目錄**：建一級分類，再往下建二級、三級分組，商品掛在三級分組下。
2. **商品類型**：一級分類的 `code` 與 `product_type` 決定商品屬於雲伺服器、遊戲雲、CDN 還是虛擬主機等業務類型，它決定官網的入口分類，也決定用戶控制台渲染哪套界面。
3. **商品**：填分組、規格、價格、配置項、庫存。
4. **計費週期與價格**：至少給一個週期的價格，其餘週期可讓系統按比例推導（見第 4 節）。
5. **折扣分組**：需要給代理商分層定價時，先在「代理折扣」建「折扣組」，再回商品上綁定（見第 5 節）。
6. **上游與庫存**：綁定供應商與上游商品，打開自動開通，庫存交給定時同步（見第 6 節）。
7. **上架**：`status` 置為啟用，官網才會銷售。

## 2. 商品分組三級結構

官網按一級、二級、三級逐層下鑽，商品**只能**掛在三級分組下。

| 層級 | 表                      | 關鍵字段                                                                          | 作用                                                   |
| ---- | ----------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 一級 | `first_product_groups`  | `code`、`product_type`、`name`、`icon`、`banner_image`、`is_visible`、`is_system` | 官網頂層分類；`code` 參與推導商品業務類型              |
| 二級 | `second_product_groups` | `first_product_group_id`、`name`、`is_visible`                                    | 導航中間層                                             |
| 三級 | `third_product_groups`  | `second_product_group_id`、`name`、`is_visible`                                   | 商品實際歸屬層（`products.product_group_id` 指向這裡） |

- `is_visible = 0` 會整層從官網隱藏。官網查詢要求三級、二級、一級**三層都可見**，任何一層關掉，整條路徑上的商品都不再出現在官網頁面上。
- 新增商品必須帶 `third_product_group_id`，否則保存失敗並提示「商品必須掛載到三級分組下」；二級分組缺少一級歸屬時提示「二級分組缺少一級歸屬」；顯式傳入的一級/二級 `id` 與三級分組的實際歸屬不一致時提示「一級分組與二級分組不匹配」。
- **只填了一級、二級分組卻沒填三級分組就提交**，是壓縮站改版時最常見的失敗點：商品不會創建，也不會有部分寫入。
- 商品類型不在商品行上直接選擇，而是由一級分組的 `product_type`（或 `code` 經歷史映射）推導後寫入 `products.product_type` 與 `service_type_code`。因此「先建對一級分類，再建商品」不能顛倒；商品建好後再改一級分類的類型，會把該分類下所有商品的類型一起改寫，官網入口與用戶控制台模板都會跟着變。

## 3. 商品字段手冊

新增/編輯入口：後台 → 商品目錄 → 新增商品，表單分「基礎」「定價」「接口」「商品配置」等分區。

**基礎**

| 字段                        | 必填     | 默認      | 影響                                                                                                                                                                                                                                                                                                                                        |
| --------------------------- | -------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `custom_display_name`       | 可選     | 空        | 商品對用戶顯示的名稱。默認由系統填成規範規格摘要（如 `2核2G`、`2核2G30Mbps`），留空時按規格（CPU/記憶體等）自動生成；兩者都取不到時顯示「未配置規格 `#<id>`」。分組層級不在商品名裡，由商品路徑（`product_full_path`）單獨展示——商品列表出現這個字符串，説明該商品的 `config_options` 或 `purchase_requires.upstream_default_config` 還沒配好 |
| `third_product_group_id`    | **必填** | 無        | 決定商品掛在哪條官網路徑下                                                                                                                                                                                                                                                                                                                  |
| `console_template`          | 可選     | `compute` | 決定用戶控制台渲染哪套界面：`compute`（雲主機語義：電源、重裝、VNC、安全組）、`port_mapping`（端口映射）、`cdn`（流量/加速區域/防護）、`virtualhost`（面板型託管）。傳入不在枚舉內的值時靜默回落到 `compute`——配錯的典型現象是「虛擬主機商品的控制台裡出現了開關機按鈕」                                                                    |
| `product_discount_group_id` | 可選     | 空        | 代理折扣分組，見第 5 節                                                                                                                                                                                                                                                                                                                     |
| `cpu_model` / `cpu_turbo`   | 可選     | 空        | 僅規格展示，不參與計價                                                                                                                                                                                                                                                                                                                      |
| `description`               | 可選     | 空        | 商品詳情富文本。落庫前過白名單消毒，防注入，保存後前台直接渲染                                                                                                                                                                                                                                                                              |
| `remark`                    | 可選     | 空        | 僅後台可見的內部備註                                                                                                                                                                                                                                                                                                                        |
| `sort_order`                | 可選     | `0`       | 同分組內排序；列表頁可拖動排序                                                                                                                                                                                                                                                                                                              |
| `status`                    | 可選     | `1`       | 上架開關，見第 7 節                                                                                                                                                                                                                                                                                                                         |

**定價與庫存**

| 字段         | 必填     | 默認 | 影響                                             |
| ------------ | -------- | ---- | ------------------------------------------------ |
| `pricing`    | **必填** | 無   | 計費週期價格，結構 `{ "monthly": "30.00", ... }` |
| `setup_fee`  | 可選     | `0`  | 初裝費，按每個實例計一次，直接加進賬單金額       |
| `stock`      | 可選     | `-1` | `-1` 表示不限量；見第 6 節                       |
| `auto_setup` | 可選     | `0`  | 自動開通開關；詳見[訂單與自動開通](orders.md)    |

**購買條件與開通參數**

| 字段                                     | 默認                | 影響                                                                                                                                |
| ---------------------------------------- | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `purchase_requires.require_verification` | 關                  | 打開後未實名用戶下單被拒：「該商品需要實名認證後才能購買」                                                                          |
| `purchase_requires.require_phone`        | 關                  | 打開後未綁手機用戶下單被拒                                                                                                          |
| `purchase_requires.provision_hostname`   | 空（等同 `system`） | 開通時的機器命名規則：`system` 系統生成、`fixed` 固定主機名、`prefix` 字母前綴 + 隨機後綴（`length` 限 4–63）。可在商品目錄批量設置 |

> `setup_fee` 雖然接口與數據庫都支持（`min:0`），但後台商品編輯頁並沒有這個輸入框，只能通過接口或其他商品批量入口寫入。（未在管理端界面中確認存在設置初裝費的入口）

## 4. 計費週期與價格

系統支持的週期枚舉（`BillingCycle`）：`monthly`（月付）、`quarterly`（季付）、`semiannually`（半年付）、`annually`（年付）、`biennially`（兩年付）、`triennially`（三年付）、`one_time`（一次性）、`free`（免費）、`ontrial`（試用，僅上游回傳）。歷史別名 `yearly`、`onetime`、`biannually` 會自動歸一化。

- **後台商品編輯頁只提供月付、季付、半年付、年付四個價格輸入框**，其餘週期不在界面上。需要更多週期時（未在管理端界面中確認入口）只能走接口。
- 保存時系統會推導：缺少某一週期價格，且月付價格大於 0，則按「月付 × 週期月數」（1/3/6/12）自動補齊。**月付留空或填 0，其餘週期也不會自動生成**。
- 校驗要求：`pricing` 必須是非空數組，且至少有一個週期金額大於 0，否則提示「請至少配置一個計費週期價格」。金額為 0 或負數的週期會被直接丟掉。
- 讀取價格時還有一層兜底：目標週期沒有價格，就用「月付 × 月數」推算；月付也沒有則金額記 0，此時下單會被拒（「無效的計費週期」）。
- 賬單金額 = `pricing[周期]` + 配置項加價 + `setup_fee`。加價明細與合計會寫進賬單的定價快照，改商品價格不會變動歷史賬單。

## 5. 配置項、加價與代理折扣

**配置項**（`config_options` JSON）：數組元素含 `form_key`、`name`、`option_mode`（`select` / `range` / `text`）、`sub[]`（子項）。計價時的字段鍵**優先取 `form_key`**，沒有才回退 `field`；兩者都取不到時按 `option_type` 映射。這解釋了為什麼同一商品裡有多個配置項時必須以 `form_key` 區分——全用 `field` 會互相覆蓋。

- `option_mode = text` 的提示項（例如「明確禁止」這類購買須知）只用於展示，不參與計價、也不寫進配置快照。
- `hidden = 1` 的配置項與子項不展示、不計價；用戶沒選的項不會產生加價。
- `range` 型按 `qty_minimum`、`qty_stage` 與命中子項的邊界算出「步數」，再乘該子項對應週期的單價。子項單價缺該週期時同樣按「月付 × 月數」折算。
- 提交值超出所有階梯且沒有「無上限」兜底段時，系統直接報「配置項「xxx」超出可選範圍」並拒單，而不是按 0 元放過。

**接了上游的商品**：配置項加價走上游 `/quote` 實時報價，再按配置項上的 `markup` 套加價。`markup.mode` 四種：`inherit`（跟隨上游，默認）、`multiplier`（上游價 × 倍率）、`fixed`（商家自定義單價 × 數量）、`both`（自定義單價 × 數量 × 倍率），三者都支持 `extra_amount` 附加費。

- 切模式時已存的 `multiplier` / `unit_price` 不會被清空，但計價按當前 `mode` 顯式分支，不會把上個模式的殘留值算進去。
- `fixed` 模式忘記填 `unit_price` 時會退化成上游成本價——表現為「自定義單價看起來生效了，實際加價是 0」。
- 上游報價接口不可達時，退化為「只算後台設了 `fixed`/`both` 且填了單價的項」，其餘項顯示 0 元。

**代理折扣**：三層設置，從粗到細。

| 設置         | 位置                       | 字段                                                               | 説明                                             |
| ------------ | -------------------------- | ------------------------------------------------------------------ | ------------------------------------------------ |
| 折扣組       | 後台 → 代理折扣            | `name`、`min_discount_rate`（默認 `100`）、`cost_rate`（默認 `0`） | 一組商品的分層定價底線與成本佔比                 |
| 商品綁定     | 後台 → 商品目錄 → 編輯商品 | `product_discount_group_id`                                        | 把商品划進某個折扣組                             |
| 代理組與矩陣 | 後台 → 代理折扣            | `default_discount_rate`、矩陣行 `discount_rate`                    | 用戶所屬代理組的全局折扣率，以及按折扣組的例外值 |

計價規則（`AgentDiscountService`，`discount_rate` / `cost_rate` 都是**百分數**）：

```text
折后金额 = 原价 × discount_rate / 100
成本金额 = 原价 × cost_rate / 100
```

取值優先級：**矩陣命中**（用戶代理組按該折扣組配了 `discount_rate`）→ 否則回退用戶代理組的 `default_discount_rate` → 都沒配則不打折（等於 100%）。代理組 `status ≠ 1`（停用）或商品沒綁折扣組時，矩陣這條路直接不成立。

三道攔截必須知道：

- `discount_rate` 必須在 0–100 之間，否則「折扣率必須在 0 到 100 之間」。
- 矩陣折扣低於該折扣組的 `min_discount_rate` 時，「折扣率不能低於商品折扣組最低折扣率」——矩陣頁面在保存前會先本地攔一道並列出具體是哪幾格。
- 折後金額低於 `cost_amount` 時，「代理折後金額不能低於成本價」。**這是唯一會在下單時阻斷用戶的成本保護**，配錯 `cost_rate`（填太大）會讓代理用戶下不了單。

疊加順序（`CheckoutService::create`）：先按商品價格 + 配置項加價 + 初裝費得到原價 → 套代理折扣 → 再扣優惠券。也就是優惠券作用在**折後價**上，實付 = 折後金額 − 優惠券抵扣，最低到 0。訂單與賬單會同時保存原價、代理折扣率、折扣額、成本額、優惠券快照，出爭議時以快照為準。

## 6. 庫存：本地值與上游真實值

- `stock` 的取值範圍是 `-1` 及以上；**`-1` 表示不限量**，也是後台默認值。
- 下游（魔方財務等）下單時讀的是 `products.stock`；本站結賬走的是「實時庫存」，即 `live_stock` 優先、缺失才回落 `stock`。同一商品兩處口徑可能不同，排查「前台顯示有貨但下單失敗」時要同時看這兩個值。
- 下單閘門在一次請求內完成「綁定商品 → 查上游庫存 → 再判斷」，判定只有一條：可用量不小於 0 且小於需求數量時拋「該商品庫存不足，無法繼續下單」。不限量（負值）不參與攔截。
- **預扣只針對有限正庫存**：`stock > 0` 才按數量扣減，並把實際扣減量寫進訂單/賬單快照的 `stock_reserved`。取消或退款按這個快照精確回補。**不限量商品下單不扣、取消也不加回**，因此不會因為「−1 賣出」而漂移。
- 上游商品的庫存由定時任務每 15 分鐘同步一次，優先級依次是：從未同步過的商品 → 已售罄或餘量吃緊（`0 ≤ stock ≤ 5`）→ 其他限量品 → 不限量品。不限量品永遠排最後，因為它只是個固定標記。
- 上游返回的庫存經常不可信（代碼註釋明確記錄了這一點）。系統還做了兜底：上游在結賬時明確拒絕「庫存不足/已下架」，本地庫存快照會**立刻歸零**並寫一條過期覆蓋，不必等下一次同步。
- 站長的實際動作：**不要把上游庫存當精確賬本**。用「商品目錄」的庫存列看趨勢，需要止損時直接改 `stock`（置 0 立即停售）；手動改過的值會在下一次同步時被上游值覆蓋。
- 驗證：找一個已上架、`stock` 至少為 1、已綁定供應商與上游商品並且 `auto_setup` 已打開的商品，用測試賬號走到報價接口能返回正數金額、下單到建單不報庫存錯。這一步過了再談放量。

## 7. 上下架對已購用戶的影響

- `status` 只有 `0` 與 `1`。`1` 為在售。官網列表只取在售商品，官網快取會在保存後清理。
- **下架不會影響已購用戶**：服務實例、到期時間、控制台操作、工單都不受影響。
- 下架會讓新購報價與下單被拒（「產品已下架」）。**續費鏈路與官網列表是兩套取數邏輯，續費不檢查商品上下架狀態**，所以老用戶仍能續費；反過來，想靠下架來停止某商品的全部收入是不成立的，需要另行處理服務實例。
- 刪除商品是軟刪除，商品列表默認看不到，要切換到「已刪除」生命週期篩選才能複核與恢復。
- **徹底刪除的代價**：它會連帶軟刪除該商品下的全部服務實例、把 `orders.service_id` 與 `tickets.service_id` 置空、刪除 `service_upstream_bindings` 與 `product_upstream_bindings`。商品可以恢復，服務與上游綁定恢復不了。執行前先確認該商品下確實沒有需要留存的實例。
- 刪除保護：商品下存在服務實例時，軟刪除與徹底刪除都會被拒（「該商品已有服務實例，無法直接刪除」），批量刪除會跳過並在結果裡返回原因（「存在服務實例」）。
- **官網快取延遲**：商品類型與分組快取 15 分鐘，商品列表與詳情快取 10 分鐘，**庫存字段單獨走 10 秒快取**。後台改商品會主動清快取，但直接改數據庫、或走遷移腳本寫入的數據不會清——改完沒生效時，先在後台重新保存該商品或調一次排序，再刷新官網。

## 8. 驗證清單

1. 官網：該商品能在正確的三級路徑下找到，價格與週期標籤與後台一致。
2. 報價：登錄狀態下走一次報價，確認金額 = 週期價 + 配置項加價 + 初裝費；代理賬號再用一次，確認折扣率與折扣額符合預期。
3. 庫存：`stock = 0` 時下單被拒且提示明確；改回正數後立刻恢復。
4. 下架：`status = 0` 後官網不再展示、新購被拒；已購用戶的續費與控制台操作照常。
5. 控制台：用測試賬號買一台或打開一個已有實例，確認操作按鈕與 `console_template` 相符。
6. 快取：改完商品在 10 分鐘內複查官網是否已更新，未更新則手動觸發一次保存。

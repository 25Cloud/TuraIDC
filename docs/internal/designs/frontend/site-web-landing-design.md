# 项目官网首页（site-web）设计

## 1. 背景与目标

文档站已经在 `docs.turaidc.com`（`docs-web/` + 仓库根 `edgeone.json`，由 EdgeOne Pages 自动部署），但它解决的是"装起来、用起来"，不是"这东西是什么、凭什么换掉我现在用的系统"。

目标是补一个**单页**产品首页：静态输出完整 HTML，承担品牌展示、搜索入口与转化，内容深度仍然交给文档站。

非目标（v1 明确不做）：

- 不做 `/features`、`/pricing`、`/blog` 等多页矩阵，先把一页做扎实。
- 不做多语言（中文优先，英文版另建设计）。
- 不在首页复制文档正文；首页只给结论与入口。

## 2. 关键决策

| 决策       | 选择                                             | 理由                                                                                                                                                                                                            |
| ---------- | ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 仓库形态   | 不新建仓库，本仓库新增 `site-web/`               | 版本号、能力清单、截图与主仓同源；新仓库会让事实漂移，还要再维护一套 CLA 与许可声明                                                                                                                             |
| Pages 项目 | 独立项目，根目录设为 `site-web/`                 | 仓库根 `edgeone.json` 的构建链（`check_docs.mjs` + `docs-web`）只服务文档站，不能让首页复用                                                                                                                     |
| 渲染方式   | Astro + `@astrojs/vue` 构建期渲染                | 单页只需要构建期把 Vue 组件渲成 HTML：组件写法不变、页面零客户端 JS。VitePress 版实测首屏 9 请求约 520 KB，大头是文档主题样式与运行时，这页用不上                                                               |
| 图标       | `tdesign-icons-vue-next`                         | 与 [视觉规范](../../../develop/design.md) 的图标约束一致，不手绘 SVG、不用 emoji 当功能图标                                                                                                                     |
| 域名       | `www.turaidc.com` 为主域，`docs.` 不动           | 不动已索引的文档 URL；首页与文档站、仓库互相链接形成内链闭环                                                                                                                                                    |
| 加速区域   | 只走境外节点                                     | 不办 ICP 备案。代价见第 7 节，接受这个折损                                                                                                                                                                      |
| 文案源     | `src/i18n/*.json` 四个语言包                     | 组件不写硬编码文案；语言代码沿用 `shared/locale`，键结构按模块嵌套，与三端语言包同一套粒度                                                                                                                      |
| 多语言     | 四份预渲染 HTML + hreflang                       | `/`（简中）、`/zh-tw/`、`/zh-hk/`、`/en/`；静态页比运行时切换更利于收录，也不需要前端 i18n 运行时                                                                                                               |
| 主题       | 明 / 暗 / 跟随系统                               | 默认跟随系统；`<html data-theme-pref>` 由首帧内联脚本写入，避免闪白；深色是浅色 token 的镜像，不引入第二套品牌色                                                                                                |
| 合作伙伴墙 | 取 README 的 Trusted Partners                    | 这几家是生态伙伴，不宣称「都在使用」；真正跑着系统的只有二五云，单独做成「在线演示」入口                                                                                                                        |
| 在线演示   | 二五云 `idc.25y.cn` 外链                         | 目前唯一跑在 TuraIDC 上的生产站，比文案更能说明系统长什么样；Hero 与伙伴区各放一个入口，统一在 `LINKS.demo`                                                                                                     |
| 系统截图   | 二五云线上站点实拍（脚本截图，产物入库）         | 手写的界面示意图和真实系统对不上，等于用假 UI 卖真系统。改用 `scripts/capture-shots.mjs` 打开线上站点截图，构建只读产物，不依赖网络与浏览器                                                                     |
| 项目动态   | 版本行用构建期快照，数字换成 shields.io 实时徽章 | 首页要能看出「还在维护」，但 Star 一天一涨，构建期快照两次部署之间就过期了。数字交给 shields.io 的图片：访问即最新、带几分钟缓存，仍是零 JS；release 版本行与历史版本则必须跟仓库版本一一对应，继续用构建期快照 |
| 社区板块   | 独立一段，插在项目动态之后                       | 项目热度、贡献者、语言构成、交流群是「要不要参与」的判断依据，和「发过什么版」是两件事；塞进项目动态会变成一锅数据，用户也找不到进群入口                                                                        |

## 3. 页面结构

单页十二段，顺序即说服顺序：

1. Hero：定位一句话 + 双 CTA（文档 / GitHub）+ 迁移入口 + 四条事实数字，右侧是二五云线上站点的商品选购页实拍。
2. 合作伙伴：README 的五家 Trusted Partners。**这几家是生态伙伴，不代表都在用 TuraIDC**；墙下面单独一条「在线演示」，指向真正跑着这套系统的二五云（`idc.25y.cn`）。
3. 项目动态：最新 release 的版本号与发布日期、11 枚实时徽章（版本 / Star / Fork / 贡献者 / issue / 最近提交 / 许可 / CI 三件套技术栈）、近五版记录。版本行来自构建期快照，徽章由 shields.io 现算。
4. 社区：项目热度（star-history 曲线）、贡献者（contrib.rocks 头像墙）、语言构成（构建期快照的占比条 + Top 5）、开发交流（QQ 群号 / 加群链接 / 二维码）。
5. 能力矩阵：八个业务域。
6. 业务闭环：商品配置 → 下单支付 → 自动开通 → 计费续费 → 财务对账 → 工单通知。
7. 安全与资金：**"我们没有"七条 vs "我们有"六条**，直接取自仓库 README。
8. 部署：Docker / 宝塔 / 裸机三条路径，各自链到对应文档。
9. 迁移：从智简魔方财务搬过来的三条路径。
10. 定价：开源版 0 元（AGPL）与商业授权 200 元/年，功能一致。
11. FAQ：六个高频问题，同时生成 `FAQPage` 结构化数据。
12. 页脚：AGPL 声明、仓库、文档、联系方式。

事实口径以仓库根 `README.md` 与 `docs/` 为准；首页只做面向访客的重写，不新增能力声明。

### 3.1 社区板块的信息层级

1. 段标题一行说清「这一块有什么」，不堆形容词。
2. 项目热度占满整行：它是这一段的唯一主图，也是「在涨」最直观的证据；曲线本身由 star-history 出，站点只负责排版。
3. 另外三张卡并成一行、顶部对齐，高度各自随内容走（不强拉等高，免得卡片里留半屏空白）：贡献者（想参与的人先看脸）、语言构成（技术栈判断）、开发交流（最后一步行动）。
4. 交流卡是这一段唯一的转化点：群号做成可选中的大字，按钮在左，二维码在右；窄屏时二维码落到下方，扫码路径不依赖 JS。
5. 图注只给事实与出处，不写「3 天前」这类会过期的相对时间。

## 4. SEO 口径

- 四个语言页各自有唯一 `title`、唯一 `h1`、canonical 指向自己，`description` 控制在 60–220 字（英文按字符计）。
- 每个页面输出四条 `hreflang` 加一条 `x-default`；语言代码用 `zh-CN` / `zh-TW` / `zh-HK` / `en`。
- 结构化数据 `@graph`：`Organization`、`SoftwareApplication`（含两款 `Offer`）、`FAQPage`；`FAQPage` 与当前语言的可见 FAQ 同源，`inLanguage` 跟随页面。
- `sitemap-index.xml` / `sitemap-0.xml` 由 `@astrojs/sitemap` 生成，收录四个语言页；`robots.txt` 在 `public/` 里静态给出并指向索引。
- 首屏零 JS：组件不加 `client:*` 指令，页面里只有两段内联脚本（主题偏好、滚动进场）；`verify-build.mjs` 会断言 HTML 不引用任何外部脚本。
- 正文可见性优先于动效：首屏用 CSS 关键帧；滚动进场只对"加载时已在视口下方"的元素生效，脚本失效、`prefers-reduced-motion`、打印三种情况都不隐藏正文。
- 构建后由 `scripts/verify-build.mjs` 把上述口径变成门禁，EdgeOne 构建命令里跟着 `astro build` 一起跑。

## 5. 图片与第三方图源

首页有几张图不在本地，靠对方按访问现出：

| 图            | 图源                                 | 尺寸声明                | 备选/降级                |
| ------------- | ------------------------------------ | ----------------------- | ------------------------ |
| 11 枚实时徽章 | `img.shields.io` + GitHub 的 CI 徽章 | 20px 高，宽度按实测写死 | 加载不到只留占位与 `alt` |
| 项目热度曲线  | `api.star-history.com`               | 800×533                 | 同上；图注指向交互版     |
| 贡献者头像墙  | `contrib.rocks`                      | 744×64                  | 同上；图注指向贡献者列表 |
| QQ 群二维码   | 站内 `public/images/qq-group.jpg`    | 1284×2280               | 本地素材，不依赖网络     |

统一加载策略：

- 每张图都写死 `width` / `height`，防 CLS；徽章另用 CSS 固定 20px 高、宽度自适应，数字变长只变宽不变形。
- 一律 `loading="lazy"`、`decoding="async"`、`referrerpolicy="no-referrer"`：这几张都在首屏以下，不该抢首屏带宽，也不该把来源页址带给第三方。
- 深色模式靠 `<picture>` + `<source media="(prefers-color-scheme: dark)">` 选图，**跟随系统配色，不跟随站内主题开关**；文案与图注不得承诺「跟随主题」。
- 不引任何第三方 JS SDK、不加 `client:*`：实时性只来自「图片地址在对方那边现算」这一件事。
- 第三方图挂掉时页面必须仍然可读：正文、链接、语言占比（本地快照）都不依赖这些图。

## 6. 视觉

沿用 [视觉规范](../../../develop/design.md) 的 token：主色 `#165DFF`、页面底 `#F5F7FB`、边框 `#E5EAF3`、主文本 `#1F2937`、系统字体栈。

深色主题是同一套 token 的镜像（页面底 `#0B1220`、卡片 `#111C2F`、边框 `#1E2B41`、主色提亮到 `#4D84FF`），换的是明度不是色相。

首页是访客页而不是后台页，允许更大字号、更强对比与动效；但不引入第二套色板与圆角，不整页铺高饱和渐变，不用玻璃拟态堆装饰。动效集中在三处：首屏入场、滚动揭示（含业务链路连线的拉开）、卡片 hover。

## 7. 已知取舍与风险

- **境外节点**：不做 ICP 备案就进不了大陆加速。大陆访客首屏会慢，百度抓取频次也低；对外传播以 GitHub、Bing、Google 与社区渠道为主。
- **没有控制台截图**：控制台与管理端要登录，线上站没有可公开的演示账号，所以首页只展示能公开截到的官网页面（选购页）。要做三端截图，得先有一个脱敏的演示账号，或者在截图脚本里走一套 mock 登录。
- **截图带二五云品牌**：图是二五云的线上站点，导航与页脚都是它自己的品牌。这是有意的——它本来就是「在线演示」指向的那个站，图注也写明了来源；后续如果自建官方演示站，重跑 `npm run shots` 即可。
- **仓库数据的时效**：Star / Fork / issue / 最近提交改成了 shields.io 的实时徽章，刷新页面就是当前数字；仍然留在构建期快照里的只有 release 版本行与语言构成，两者都只在部署时刷新。页面不写「3 天前」这类相对时间，避免隔天就失真。
- **第三方图源的可用性**：徽章、曲线、头像墙都指向别人的主机。大陆访问 shields.io / star-history 可能慢或被墙，届时这几块只剩占位框。接受这个折损：要自己托管就得跑代理服务，等于多一台要维护的机器，收益对不上。
- **深色版图表只有 star-history 自己那版**：它的深色底色和站内深色卡片不完全一致，不打算用 CSS 滤镜硬凑——滤镜会把曲线颜色也一起改掉。
- **文案漂移**：能力清单、许可价格两处最容易和 README 走散。规则是改 README 事实时同步 `src/i18n/zh_CN.json`，反向不成立。
- **翻译一致性**：`zh_TW` / `zh_HK` 由 `zh_CN` 经 OpenCC 生成后再人工抽查，`en_US` 为手写。改文案时先改简中，再重跑转换脚本，最后过一遍繁体用词（如「影片/軟體」这类语境差异）。
- **配置归属待验证**：EdgeOne 说的是"项目根目录下的 `edgeone.json`"，需要确认根目录设成 `site-web/` 后读的是 `site-web/edgeone.json` 还是仓库根那份。验证与回退步骤见[执行计划](../../execution-plans/active/site-web-landing-2026-10-24.md)。

### 优化

- **官网加载统一为骨架动画**：移除页面级 `v-loading` 遮罩与转圈，首屏 `#app-splash`、顶栏用户区、路由切换、首页各 section、帮助/公告/关于/联系/SEO 落地页与移动端抽屉统一使用与真实布局同尺寸的骨架扫光（1.2s），`prefers-reduced-motion` 下静止；异步内容到达后原地替换，不再白屏或整页遮罩
- **术语统一为「商品 / 实例」**：三端 12 个语言包 842 处文案与菜单/路由 20 处口径统一——销售对象一律「商品」（Product），开通后对象一律「实例」（Instance），保留「服务条款 / 客服 / 服务器 / 服务支持」等固定搭配；SEO 落地页 CTA 与内容搜索关键词同步修正
- **侧栏商品目录动画重做**：目录两栏内层固定展开宽度，收起改为裁切 + 位移 + 淡出（260ms `cubic-bezier(.4,0,.2,1)`），宽度过渡期间文字不再被逐帧挤扁；一级分组折叠时文字区定宽淡出、图标滑到窄栏中心；手机端抽屉内目录钻取/返回改为 240ms 淡入上移，开关图标与手机入口箭头补旋转反馈
- **一级分组图标收口到内置图标库**：管理端移除媒体库图片上传/图片地址入口，只保留 TDesign 图标选择器；`ProductGroupIcon` 解析优先级改为 `icon → icon_text → 缩写`，历史值（Platform / Gamepad / Grid / Node / Network 等）统一归一为真实 kebab 图标名，`icon_image` 列保留但不再渲染与写入
- **生产库清理与运维健康**：清理下架/上游失效商品——无任何历史关联的 238 个商品连同其上游绑定硬删，仍挂着终态实例或历史订单账单的 109 个商品软删（保留行供订单/账单/服务关联），仍有开通中/已开通/已暂停实例的 56 个原样保留；随后删除 43 个已无商品的三级分组、修正 5 个重复 slug。运维侧：`log-archive` 定时任务此前一直失败（服务器没装 `pt-archiver`、`/etc/turaidc/pt-archiver.cnf` 也不存在），日志表只增不减涨到 232MB，现已安装 Percona Toolkit 并落地配置文件，一次归档清除 291609 行超期日志（导出 CSV 留档）；清空 152 条历史失败队列；把 7 个已过期仍为「已开通」的服务收敛为暂停
- **商品名统一成「三级分组名 + 规范规格摘要」**：此前商品名直接沿用上游自由文本——「宿迁AMD 锐龙 Threadripper 3960X三线BGP 2G2H」「枣庄BGP 13900K 2核2G」「襄阳一区 2H2G20M」与只有配置的「2vCPU2GiB」混在一起，核数写 2核 / 2H / 2C、内存写 2G / 2GiB / 2048、带宽有的写 20M 有的干脆没有，同一目录里横向比较完全对不上。现在展示名统一为「三级分组名 + 核数内存带宽」，如「宿迁BGP Threadripper 3960X 2核2G30Mbps」「湖北襄阳 电信 2核2G20Mbps」：规格摘要由商品自己的结构化配置算出，配置给的是规格族（4核 / 8核 / 12核…）时从商品名里取具体档位并用规格族校验，型号数字（13900K、3960X）不会被当成规格；虚拟主机 / CDN / 挂机宝这类没有处理器规格的商品保持原名。生产库 748 个在售商品已按新口径改名（旧名留有 SQL 备份）。对接同步行为不变，同步完新商品可执行 `php artisan product-catalog:normalize-product-names --execute` 再规范化（幂等，默认 dry-run）
- **控制台服务实例按一级分组切分**：此前「服务实例」列表只有一个不起眼的「服务分类」下拉，云服务器 / 游戏云 / 虚拟主机混在一起，看不出自己每个产品线有几台机器。现在桌面端列表上方是一条一级分组 tab，第一项是「全部产品」，每项带该分组的实例数（取自 `grouped-overview` 的一级分组统计），点一下就切到该组；窄屏仍用同源的下拉，两者改的是同一个筛选值。切换后地址带上 `catalog_type`，刷新和分享能停在同一分组，仪表盘的「我的产品」磁贴跳转也走同一条路
- **选购页目录导航重做：一级分组与二 / 三级分组分成两个侧栏**。此前一级分组和二 / 三级分组挤在同一列里（后者字号只有 12.5px / 13px），点开三级分组要在一堆小字里找；现在桌面端左边一栏只放一级分组（可折成缩写方块），右边一栏只放当前一级分组下的二 / 三级分组，字号统一到 13.5–15px。点二 / 三级分组时左边一栏自动收起，把宽度让给配置区；顶部「分组顶部 / 分组侧栏」二选一开关换成「收起 / 展开目录」（偏好存本机），不再需要为放哪儿做选择。手机端不再先弹一整页一级分组卡片、再在顶部折叠面板里选二 / 三级分组：展示方式条左侧的当前层级就是目录入口，点开一个底部抽屉——一级分组是横向标签，点二级分组原地钻取三级分组（带返回），选完自动收起
- **选购页目录加载变快、不再时快时慢**：此前打开一个目录要先拉分组，再把每个三级分组的商品逐个拉一遍（最多 30 个子分组就是 30 多条请求），卡片式还会额外预取 8 个商品详情，加上首页重复请求 `/v2/site/config`，一条链路三十多个请求、好几秒才出内容；服务端本身是毫秒级，慢在请求扇出与网络往返。现在新增聚合接口 `GET /v2/site/product-groups/{group}/catalog`，一次返回二级/三级分组与该目录下的商品，服务端按 `site-products` 标签缓存 5 分钟（目录变更自动失效）；前端目录缓存从只存内存改为内存（3 分钟）+ `sessionStorage`（60 秒，按登录态分区），刷新页面不再全部重拉；三级分组商品改为点开才拉，卡片式不再预取商品详情，首页去掉重复的 config 预取

### 修复

- **管理端/控制台「同步信息」不再被电源状态读取失败阻断**：实例 3783（用户 1086）点同步返回 `{"code":42200,"message":"电源状态失败，请稍后重试"}`，原因是同步先读电源状态、上游关机或暂停时读不到就抛错，后面的实例详情刷新被中断；且管理端 `loadDetailBase(forceRefresh)` 丢失了 `refresh=1` 参数，详情只读缓存。现在 `type=host` 的电源状态读取失败降级为 `available=false`（写 warning 日志，不抛 42200），前端无论电源状态成功与否都强制拉取最新详情（到期时间、商品、IP、状态），只提示「实例信息已同步，电源状态暂时不可用」

- **业务异常在未启动容器的场景下不再抛错**：v0.4.1 起 `BusinessException` 构造时会查翻译表，而裸 PHPUnit 场景与配置缓存、队列反序列化等早期启动路径尚未绑定 `translator`，取译文反而抛 `BindingResolutionException` 把业务异常替换掉；现改为取译文失败即放行中文原文

### 测试与工程

- **e2e 在各端 Playwright 配置里钉住 UI 语言**：界面语言改为按浏览器偏好自适应后，宿主语言为英文的环境会让「断言写中文」的用例整批变红（控制台一次跑出 13 failed / 7 passed，全部是环境差异而非回归）。改为在配置层钉 `locale: 'zh-CN'`，一处覆盖全部用例；控制台随后 20 passed / 0 failed

- **硬编码中文改为债务棘轮**：482 处存量按「app → 文件 → 处数」冻结在 `TEMPLATE_CHINESE_BASELINE`——清单外的文件出现中文即失败，清单内文件处数超过登记值即失败（消息带 `89 → 90` 差值），变少则通过。既堵死新增，也把欠账摊开记账。守卫本身已用「基线绿 → 调低 1 即红 → 还原复绿」验证过确实会红

## [v0.3.5] - 2026-09-05

### 修复

- **被魔方财务对接持续 405**：登录与鉴权的账号条件不一致——登录只校验 API 开关与密码，鉴权中间件额外要求账号启用，账号停用时形成「登录成功 → 每次请求 405 → 强制重登 → 再 405」死循环。现登录与鉴权条件对齐，停用/关闭 API 的账号登录直接拒绝；405 响应细分原因（JWT 失效/账号不可用/API 未开放）并记录日志便于定位
- **对接智简魔方财务续费假成功**：续费周期下拉此前由本地商品定价派生（仅配月付价也会派生出季/半年/年），用户选中上游不支持的周期后本地扣款成功、上游「换周期续费」被拒，履约失败且用户不可见。现续费周期按上游 `/host/renewpage` 官方可续周期收敛（本地定价与上游集合取交集），预览、建账单、建订单、自动续费共用；上游不可达时回退本地集合并告警
- **leaf 实名认证签名失败**：签名算法对齐官方 SDK 规范——签名串改为 `METHOD\nPATH\nTIMESTAMP\nNONCE\nBODY_SHA256`，时间戳使用毫秒 ISO8601（`.000Z`），签名 PATH 不含域名与 query；平台业务错误从 `{error:{code,message}}` 子对象展开映射为中文提示

### 新增

- **充值实名开关**：`finance.recharge_requires_verification`（默认开启，行为与既往一致），管理端设置页新增「账户与财务」分组可关闭，面向非大陆主体部署允许未实名用户充值
- **代理组全局默认折扣率**（`agent_groups.default_discount_rate`）：折扣矩阵未覆盖的商品（未挂折扣组/折扣组停用/矩阵无记录）按默认折扣率兜底生效，矩阵命中优先；管理端代理组表单可配置，留空保持仅矩阵生效的既有行为
- 被对接补充 `/provision/button` 控制按钮接口（`id` + `func` 分发电源/VNC 操作）与硬关机、硬重启支持
- 官方文档站新增 [TuraIDC 作为上游被魔方财务对接参考](../develop/integrations/zjmf-upstream-api.md)（hostname 前缀、账号要求、状态码语义与 405 排查指引）

### 变更

- 后端测试提速与稳定性：`redis_volatile` 缓存 driver 可经 `CACHE_VOLATILE_DRIVER` 覆盖（测试环境切 array，无需真实 Redis）；测试基类适配本机 mysql CLI 路径；修复两个既有坏测试；测试文档新增 Windows 直跑 phpunit 的快速路径指引

### 升级提示

- 执行 `php artisan migrate`（`agent_groups` 新增 `default_discount_rate` 可空列，不配置不影响现有行为）
- 需要全局代理折扣的站点，到管理端「代理折扣 → 代理组」配置默认折扣率
- 对接魔方财务的站点，确认上游 hostname 为 `https://域名/api/v2/zjmf` 形式（详见对接参考文档）且对接账号处于启用状态

## [未发布]

### 修复

- **卡片式商品描述被截断、与详情页不一致**：分组浏览的卡片数据源（`ProductGroupV2QueryService::paginateSiteProducts`）只选了 `remark` 没选 `description`，描述服务于是回退到 `varchar(255)` 的历史上游描述——卡片显示到半句就断，还会带出 remark 里的「系统」等旧行，点进配置页看到的却是完整 `description`。现已补齐查询列，卡片描述与详情页使用同一份完整描述
- **卡片式描述排版**：自动生成的规格列表与上游卡片列表由两列改为一行一项；去掉描述区 136px 限高截断，长描述不再只显示前几行；自动生成的描述不再拼「系统」维度（操作系统是下单时才选的配置项，不属于商品规格）
- **卡片整块误触进入配置页**：卡片正文（商品名、描述）不再绑跳转，去掉 `role="link"`、键盘触发与悬停位移；只有「立即选购」按钮进入 `/products/:id` 配置页

## [v0.4.2] - 2026-10-19

v0.4.1 之后的累计发布（44 个提交）。主题是**选购页展示形态与分组导航重做**、**商品数据与上游一致性修复**与**管理端列表体验统一**。

### 新增

- **选购页支持列表式 / 卡片式切换**：后台「商品展示」设站点默认形态，访客可在选购页分组筛选条右侧自行切换，偏好记在本机 `localStorage`（不写后端、不影响其他访客）。卡片式把商品与配置页拆开——卡片承载名称、描述、价格与立即选购，点击进入已有的 `/products/:id` 独立配置页
- **卡片式视觉重做**：顶部「商品类型 + 库存」徽标、加粗商品名、自动生成的规格列表改为两列标签卡片、底部大号价格与主按钮；新增键盘可达（Enter/Space 进入配置页）
- **卡片式地址保留目录**：未选中商品时地址不再是裸 `/products`，而是 `/products/:typeId/:groupId/:childGroupId`（三级分组直接作为路径段），刷新与从配置页返回都能回到原分类；旧的商品深链三段路径仍兼容
- **独立配置页可切换列表 / 卡片**：`/products/:id` 顶部增加展示方式切换，切列表式带着当前商品回到列表配置页，切卡片式回到该三级分组的商品网格
- **分组导航改为纵向折叠 + 可放侧栏**：二级分组纵向排列，点开后纵向列出三级分组，不再用横向 tab 与左右箭头滚动；访客可把整组导航移入左侧栏（偏好只存本机），手机端默认收起、展开时向下推内容而不是浮层遮挡
- **修正二 / 三级分组标签**：选购页此前把二级、三级分组分别标成「一级分组」「二级分组」（与侧栏真实一级分组撞名），现在按层级显示「二级分组 / 三级分组」
- **访客可调宽屏版心**：选购页右上角「页面宽度」面板可选固定宽度（1200 / 1280 / 1440 / 1600 / 1920）或撑满屏幕，偏好只存本机 `localStorage`（`turaidc:shop-page-width`）；切换用 `max-width` 0.34s 过渡，独立配置页跟随同一选择
- **手机端可切换列表 / 卡片**：展示方式切换条在移动端也显示（此前只在桌面渲染，手机上改不了）
- **管理端插件管理支持列表 / 卡片切换**：插件多起来后需要逐行扫状态与最近运行记录；切换条与其它列表页一致放在工具条右侧，卡片视图保留原有信息，列表视图复用同一套操作按钮（启用条件不分叉）
- **服务实例独立成「服务管理」菜单分组**：此前挂在「工单处理 → 服务与工单」下，服务开通/到期/续费入口与工单混层；现为独立一级分组，工单分组只保留工单列表、传递设置与预回复设置
- **商品描述**：新增 `products.description` 富文本列，管理端提供结构化（键值对增删改排序）与高级（直接改 HTML 源码）双模式编辑器；落库前过 `RichHtmlSanitizer` 白名单，前台按原样渲染
- **描述留空时按规格维度自动生成 `<ul><li>键: 值</li></ul>`**，复用 `ProductSpecHighlightService` 已有的 21 维识别（与列表页 `spec_highlights` 同源），只读不写库，识别规则改进后历史商品立即生效
- **管理端补齐可点击链接**：用户、实例、订单、工单、商品等列表与详情页里「有 ID 却点不动」的位置改为可跳转（23 处），并抽出 `utils/route/adminEntityLink.ts` 收敛重复跳转逻辑
- **语言首屏自适应与持久化收敛**：三端共用 `shared/locale` 的归一化与探测逻辑，首次访问按浏览器语言自动选择（显式选择优先于探测），存储 key 按应用区分——此前管理端与控制台共用 tdesign 遗留 key，同域部署会互相覆盖偏好；三端 `<html lang>` 也统一跟随实际语言

### 修复

- **「云服务器/华中」页面 500**：规格取值清洗用 `trim($value, '，,;；')` 去首尾标点——`trim` 是字节级操作，中文标点含 0x8C 字节，会把「100M下行」末尾的 0x8C 一并裁掉，产生非法 UTF-8，接口 JSON 编码失败。改为正则按字符去首尾标点，并补单测
- **失效商品隔离**：254 个上游商品已不存在/供应商不可达、但仍在售的商品已下架（`status=0`），并统一移入隐藏分组「失效商品（一级分组 → 二级分组 → 三级分组）」；分组 `is_visible=0` 不出现在前台站点。改动前的商品清单与旧分组已备份到服务器 `/tmp/isolate-invalid-backup-*.json`
- **选购页细节**：卡片式手机端不再显示没有作用的「产品规格选择」；手机端补回「切换一级分组」入口（此前移除旧分类抽屉后无法返回）；分组导航去掉「二级分组 / 三级分组」字样，只展示实际分组名
- **商品描述与上游不一致**：上游商品描述此前从未导入 `products.description`；历史导入把转义后的描述 HTML 存进 255 字节的 `remark`，既被截断又因未解码而无法解析；更关键的是站点商品查询（`ProductV2QueryService` 的列表/详情列）从来没有选 `description` / `remark` 两列，前台描述服务永远读到空值，只能退回按规格拼描述。现在导入时把完整上游描述解码、补列表容器、过白名单后写入 `description`；描述为空时优先回退 `remark` 中的上游描述，最后才按规格维度自动生成；查询列已补齐。线上已从上游目录回填 879 条商品描述
- **规格亮点 / 自动描述解析错误**：`remark` 里的 HTML 实体未解码，导致整段上游描述等于没读（硬盘、防御、流量、线路全部丢失）；导入数据给所有配置项补了 `qty_minimum=0`，下拉项被误判为「最小值为 0」而丢值；商品名「4C4G20M」的 C 未被识别成核；容量行（硬盘 30G）被误判成内存；`varchar(255)` 截断留下的非法字节会让规格 JSON 编码失败。均已修复并补单测
- **上游商品配置项全量校准**：执行两轮上游配置同步（保留本地 pricing / default_value / markup），分别更新 957 / 958 个商品的配置项；抽样核对 QX / ZX / MC 的三个商品，配置项名称与顺序已与上游完全一致。另对 10 个上游 ID 失效、但名称在同一供应商内唯一匹配的商品做了重新绑定
- **上游商品数据巡检结果**（未自动改状态，需站长确认）：311 个商品绑定指向当前上游目录已不存在的商品，其中 246 个仍在售（重新绑定 10 个后约剩 301 个 / 236 个在售）；FS 供应商域名 `ww.stay33.cn` 无法解析；QS 拉取超时。这些商品的配置与描述无法再与上游对齐
- **选购页二 / 三级分组名称错位**：主区域把二级分组标成「一级分组」、三级分组标成「二级分组」，与侧栏真实一级分组重名；改为按层级显示「二级分组 / 三级分组」，并移除旧的横向 tab 行
- **选购页从独立配置页返回时整块空白**：布局层给路由视图套了 `<transition name="page-fade" mode="out-in">`，但 `.page-fade-*` 样式从未定义，返回时视图卡在离场态——路由已切回分类页，`<main>` 里只剩注释节点，必须刷新才恢复。移除这层没有实际动效的过渡
- **工单预回复设置页排版**：保存按钮孤零零贴在卡片右上角、开关与说明文字紧贴、文本域宽度不统一。现补齐「页头说明 + 右侧保存」结构，控件与说明统一 12px 可换行间距，文本域撑满整行，平板竖屏与手机改为单列全宽
- **官网整站白屏**（P0）：v0.4.1 国际化时 `import { t } from '@/locales'` 被插到了 `.vue` 文件第 1 行、即 `<template>` 标签**之外**，SFC 解析器直接忽略，导致 setup 阶段抛 `ReferenceError: t is not defined`，布局与首页组件整个挂掉。构建、类型检查、`vue-tsc` 全部无法发现，只有运行时才暴露。受害文件：官网布局、首页轮播、首页商品 Tab
- **i18n 守卫从未生效**：`test_templates_have_no_hardcoded_chinese` 有两处缺陷——`preg_match_all(...) === 1` 把「匹配条数」写成了布尔比较（真实页面几十处命中时条件恒为假），命中后又用 `str_contains($text, "\n")` 整条跳过（而 Vue 模板文本节点几乎总带缩进换行，真命中全被放过）。修好后暴露三端共 **482 处**模板层硬编码中文，长期无人发现
- **繁体用户会拿到简体界面与简体业务消息**：`zh-Hant-HK-MO` 这类标签原先只退回主语言匹配，`zh-hant-hk-mo → zh` 被判成简体中文；改为逐级前缀回退，前端 `shared/locale` 与后端 `SetLocale` 同步修正
- **业务异常在未启动容器的场景下不再抛错**：v0.4.1 起 `BusinessException` 构造时会查翻译表，而裸 PHPUnit 场景与配置缓存、队列反序列化等早期启动路径尚未绑定 `translator`，取译文反而抛 `BindingResolutionException` 把业务异常替换掉；现改为取译文失败即放行中文原文

### 测试与工程

- **e2e 在各端 Playwright 配置里钉住 UI 语言**：界面语言改为按浏览器偏好自适应后，宿主语言为英文的环境会让「断言写中文」的用例整批变红（控制台一次跑出 13 failed / 7 passed，全部是环境差异而非回归）。改为在配置层钉 `locale: 'zh-CN'`，一处覆盖全部用例；控制台随后 20 passed / 0 failed
- **模板扫描口径修正为「栈式取根 `<template>` 块」**：原先每份 `.vue` 只扫到文件里**第一个** `<template>` 段，选购页这类 3000+ 行的 SFC 从第二段起完全落在检测外；而按「开标签 → 其后第一个闭标签」的线性配对又会在嵌套 `<template #slot>` 的内层闭合处提前截断。现取根块（含标签，保证 `>文本<` 判据可用），既覆盖全部嵌套内容也不重复计数
- **硬编码中文改为债务棘轮**：482 处存量按「app → 文件 → 处数」冻结在 `TEMPLATE_CHINESE_BASELINE`——清单外的文件出现中文即失败，清单内文件处数超过登记值即失败（消息带 `89 → 90` 差值），变少则通过。既堵死新增，也把欠账摊开记账。守卫本身已用「基线绿 → 调低 1 即红 → 还原复绿」验证过确实会红

### 兼容

- 展示方式默认列表式，升级后行为与此前完全一致；存量商品描述为空即走自动生成，无需回填
- `remark` 列职责不变（内部备注 + 回传魔方 `description`），魔方对接、展示名兜底与订单快照均不受影响

## [v0.4.1] - 2026-10-15

v0.4.0 之后的累计发布（22 个提交）。主题是**界面国际化（四语言）**、**面板型商品配置项按魔方口径提交上游**与**品牌主题后台可配**。

### 新增

- **界面国际化，支持简体中文 / 繁體中文（台灣）/ 繁體中文（香港）/ English**：管理端、用户控制台、官网三端统一接入 vue-i18n；繁体按地区分别用词（台灣「網路、資料、記憶體、軟體」，香港「網絡、數據、記憶體、軟件」），由 OpenCC `cn->twp` / `cn->hkp` 生成
- **语言切换器**：管理端与控制台放在设置面板，官网放在页脚；Element Plus 组件语言随切换生效（改由 `<el-config-provider>` 承载）
- **后端业务异常消息支持四语言**：611 条 `BusinessException` 消息按 locale 返回译文，未翻译自动回落中文；语言协商优先 `X-Locale` 头，其次 `Accept-Language`
- **品牌主色与圆角改为后台可配**，三端统一
- **面板区域首屏全量预热**，并加后台开关控制
- **商品控制台面板新增虚拟主机类型**，管理端判定同步补齐
- **i18n 规范与护栏**：`docs/develop/i18n.md`（含翻译边界）与 17 项自动化测试

### 修复

- **虚拟主机与 CDN 配置项按魔方口径提交上游**：此前本地直接拿 `field` 当键，而上游把这两种商品的全部配置项 `field` 都给成了 `cpu`，导致官网只剩一项可见、选中值互相覆盖、订单规格与计价取错值；改为按「配置项 id → 子项 id / 数量」提交，与魔方 `Host.php` 一致
- **未预期异常不再被掩码成通用文案**：`api/*` 缺少兜底渲染器，Laravel 默认返回英文 `Server Error`，前端只信任中文消息，于是管理员只看到「保存员工失败」而无任何线索；现返回带请求编号的中文文案，可直接关联日志定位
- **操作日志写入补兜底**：日志失败不再把已成功的业务动作顶成 500
- **控制台面板运行时 404 与图标缺失**
- **NAT 产品控制台出现两个功能重复的 tab**
- **手机端无法切换一级分组**，并统一商品分层术语
- **康乐上游无余额接口**：不再声明余额能力，也不再伪造 0 余额
- **官网桌面端商品页补齐 CPU/内存 配置项**，弹性配置不再只能吃默认规格
- **官网结算栏「合计费用」与「/月付」被拆行**，并收敛价格字号
- **控制台换绑手机与邮箱补上原号码验证码入口**

### 文档

- 补工程踩坑记录与现网增量更新的实测坑

## [v0.4.0] - 2026-10-13

v0.3.6 之后的累计发布（73 个提交）。主题是**结算与履约链路的资金安全加固**、**魔方财务双向对接打通**与**官网/控制台表现层统一**。

### 新增

- **魔方财务（ZJMF）双向对接全链路协议**：上游侧补齐 OS 配置项下发与重装 OS 参数三级适配、`sub id` 反查真实值、工单 `create`/`reply` 端点、删除推送与暂停健壮性；中间层补 host header、自定义模块页、操作透传与流量图表端点；下游侧新增 `/api/host/sync` 接收端（验签 + 状态/连接/到期镜像同步，legacy 签名兼容 int/string 两种 id 形式），并落地 `ProvidesHostTermination` 契约与 `/host/cancel` 终止销毁——到期自动取消改为「预检 → 销毁上游 → 写前重读」三段式编排
- **商品分类三级层级显式分层**：同类型一级菜单不再并项，层级关系在菜单与列表中显式呈现
- **单域名子路径与多域名双部署**：官网与控制台既可是同源子路径，也可是独立域名；登录注册导向与代登录地址同步统一
- **首页轮播图与导航栏效果**
- **CDN 专属控制台**，含面板信息预加载
- **虚拟主机控制台**与账户设置，并修复手机端若干视图问题
- **实例详情页对齐用户端细粒度控制台**
- **支付账单查看**入口
- **后台缓存状态页与缓存清理**
- **`app:doctor` 环境自检命令**，含禁用函数检测
- **用户控制台设置抽屉入口**
- **上游售罄校准与开通门禁**：被上游以库存不足拒绝后，立刻归零本地库存快照，避免继续超卖
- **校验文案中文字段名词典**：表单校验的中文字段名集中维护，不再散落在各控制器
- 商品目录拖动排序；组件报价新增加价选项；结算栏常驻

### 变更

- **UI 体系收敛**：圆角统一为容器 6px / 控件 3px，官网与控制台设计语言对齐
- **`user_coupons.uid` 更名为 `coupon_code`**：该列实际存储券码串（`uc_xxx`），与生态内 `uid` = 用户 ID 的既有语义（`users.id`、JWT claims、上游 API）直接冲突、易引起误用；列与唯一索引（`user_coupons_uid_unique` → `user_coupons_coupon_code_unique`）一并更名

- 账单支付方式收敛为单一组装点
- 供应商状态汇总下沉到查询服务，控制器不再直接查库
- 合作伙伴条幅本地化，并修复横向滚动右侧露空

### 修复

- **被魔方财务对接持续 405**：登录与鉴权的账号条件不一致——登录只校验 API 开关与密码，鉴权中间件额外要求账号启用，账号停用时形成「登录成功 → 每次请求 405 → 强制重登 → 再 405」死循环。现登录与鉴权条件对齐，停用/关闭 API 的账号登录直接拒绝；405 响应细分原因（JWT 失效/账号不可用/API 未开放）并记录日志便于定位

### 修复

- 短信找回密码报"短信服务暂不可用"：

  - 新增"每分钟/目标号码"限流（默认 1 条），提前拦截避免打到服务商触发阿里云频繁限制

- 人机验证（Corptcha）内嵌组件预先完成被重置回退：
  - 无挂起动作时保留验证结果（`verifiedResult` 一次性消费），按钮触发时取出并重置组件，保证 token 单次使用
  - 未完成验证时点击操作先提示"请先完成人机验证"再唤起组件（登录/注册/找回密码/换绑手机邮箱）

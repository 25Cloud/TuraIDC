# 管理端设置信息架构与字段排版整改

## 背景

管理端设置类页面在真实使用中被反馈为「分类混乱、命名不自解释、描述与控件挤在一行、大片空白、废话文案多」。逐页读代码与实拍生产后确认问题不是零散样式，而是三件事：

1. **信息架构错位**：站点信息一张表单里混了品牌标识、联系客服、备案合规、通知总开关 17 个字段；`finance` 这个 tab 只有 1 个字段且没有任何路由能到达，是不可达的孤儿配置；侧边栏「日志归档」路由没有菜单入口，只能手输 URL。
2. **命名不自解释**：同一页出现 4 组「执行频率 / 执行时间」，`ticketTaskInterval`、`cleanupInterval`、`ticketRunAt`、`cleanupRunAt` 这种半吊子区分；路由标题「首页装修」与菜单标题「首页 Banner」指同一个页面。
3. **字段排版不统一**：描述与控件同行的写法至少三种并存（标签+开关+描述同一行、说明塞进 textarea placeholder、描述被控件挤成两行），保存按钮有三套位置（底部操作条 / 卡片标题行右上 / 卡片右下），全站 input 的 placeholder 默认是「请输入 + 标签」的复述。

非目标：不改后端设置项契约（group/key 不动），不改接口，不重做管理端视觉风格。

## 范围与验收

- [x] 管理端设置页按「一段一件事」重组分段，`finance` 死 tab 消灭且旧书签不 404。
- [x] 同一页重复概念全部改名到可区分（5 对定时字段带任务域前缀）。
- [x] 侧边栏分类与命名收敛：`首页 Banner` → `首页轮播`、`数据库状态` → `数据库与缓存`、日志中心拆为「日志查询 / 保留与归档」，`/admin/log-archive` 补上菜单入口。
- [x] 所有设置类表单统一为「标签一行 / 说明一行 / 控件一行」，开关字段说明独占下一行整行。
- [x] 保存操作统一到内容底部右对齐的 sticky 操作条。
- [x] 删除复述标签的 placeholder 与无信息量说明，placeholder 只留空或真示例。
- [x] 三端（管理端 / 用户控制台 / 官网）设置相关页面在 1600 / 1024 / 390 三档视口下无横向滚动、无控件被压变形。
- [x] 中文文档里指向已下线设置入口的引用同步更新。

## 实施步骤

1. 抽出全局字段排版样式 `frontend-admin-v3/src/style/admin-field.less`（`admin-field` / `admin-field--switch` / `admin-field-grid` / `admin-field-section`），在 `src/style/index.less` 引入，作为所有设置类表单的唯一排版来源。
2. 重写 `frontend-admin-v3/src/pages/settings/index.vue`：删掉从未渲染的 `tabGroups` 与死 tab `finance`；`site_basic` 拆成品牌与外观 / 联系方式与客服 / 备案与合规 / 通知渠道总开关；`automation` 收敛成故障隔离的五段；`referral` 吸收 `finance` 的孤儿字段并改叫「推荐与充值」；所有分段一次顺序铺开，不再用 radio 一次只看一段。
3. 首页轮播页：每张卡字段加「轮播 N ·/卡片 N ·」作用域前缀；把 5 张卡里重复 5 遍的说明提到节头写一次；新建轮播不再默认挂第一支视频。
4. 插件配置页：补渲染插件 schema 里的 `description`（此前完全没显示，管理员只能猜参数含义），分节样式与字段栅格统一。
5. 其余设置页（商品展示 / 工单预回复 / 工单传递 / 通知模板详情 / 开放接口 / AI 设置）对齐同一套排版与保存位置。
6. 侧边栏菜单（`src/store/modules/permission.ts`）与路由标题改名、补日志归档入口。
7. 用 Playwright 对 25 个设置相关页面 × 三档视口实拍复核，逐页对差。

## 风险与回滚

- 风险：设置项 `group/key` 不动，只动展示层，回滚只需回滚前端产物；`frontend-admin-v3/dist` 重新构建即可恢复。
- 风险：`pending_order_cleanup_*`、`pending_recharge_cleanup_*` 四个设置项在页面上移除。证据是它们只有 `SettingService` 默认值与 `ScheduleTaskService` 展示在读，真实清理走 `CheckoutSecurityService::paymentSessionTtlSeconds()`（写死 300 秒），开关不改变行为。后端默认值与展示项是否一并清理另开一刀。
- 风险：`smoke.spec.ts` 里三个设置页用例写的是早已下线的 `/admin/settings/site/basic` 与 `.field-card`，本次同步更新为新路由与新选择器；其余 e2e 断言不受影响。
- 回滚条件：设置页出现保存失败、字段丢失或分组串味时，回滚前端 dist 即可，无需回滚数据库。

## 遗留与后续

- 管理端 6 个吸底操作条各有自己的类名（`settings-bottom-actions` / `product-display-actions` / `ai-settings-actions` / `ticket-pre-reply-actions` / `ticket-delivery-actions` / `config-actions`），行为已统一但没抽公共组件，下次调整要改 6 处。计划抽成 `<SettingsActionBar>`。
- 管理端 AI 浮球是固定定位，列表类页面滚动时仍可能压住行尾按钮；已把浮球抬到 `bottom: 88px`（≤960px 时 96px）避开吸底条，行内遮挡属浮动按钮固有代价。
- 首页轮播页高度从 3016px 增到 5108px：这是「说明与控件分行」的必然代价，短字段已在卡内两列并排，不打算再压缩。
- 后端 `setting` 表里 `pending_order_cleanup_*` / `pending_recharge_cleanup_*` 四个设置项已无页面入口且不影响清理行为，后端默认值与展示项待单独清理。

## 决策日志

| 日期       | 决策                                                             | 原因                                                                                                 |
| ---------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 2026-10-26 | 设置页从「一次一段 + radio 导航」改为所有分段顺序铺开            | 一次只看一段导致卡片高度只有当前段，页面大面积空白；顺序铺开才能让用户一眼看到全貌。                 |
| 2026-10-26 | 死 tab `finance` 并入「推荐与充值」而不是单独给路由              | 一个字段不值得一个 tab；并入后旧书签 `?tab=finance` 规范化到该页，不产生 404。                        |
| 2026-10-26 | 通知渠道总开关留在站点设置页，不迁到插件管理                     | 该页权限是 `site.view`，迁走会牵扯页面权限与菜单口径，收益低于成本。                                 |
| 2026-10-26 | 日志归档挂到日志中心的「保留与归档」，不并入系统设置的「自动化」 | 归档与「日志清理」是同一类运维动作，放一起；系统设置的「自动化」只保留业务定时任务。                 |
| 2026-10-26 | 开关字段让开关与标签同行、说明独占下一行整行                     | 开关只有 44px 宽，强行换行会浪费一整行；说明与控件分行才是这次要解决的挤压问题。                     |
| 2026-10-26 | 首页第二屏的骨架屏不视为缺陷                                     | 实拍复核：滚动后骨架 4 → 0、正文长度 679 → 909，是 IntersectionObserver 懒挂载的正常表现，非死骨架。 |
| 2026-10-26 | 官网没有公告时整段不渲染「资讯动态」区块                         | 撤掉骨架屏后只剩节头 + 查看更多、下面零卡片，看着像加载失败；无数据就不给入口。                       |

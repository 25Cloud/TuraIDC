# 上游绑定切换提速与状态同步降级

## 背景

生产实例 `3783`（用户 `1086`）把上游主机改到 `10308`，界面报「失败」，但库里其实已经写完；「同步信息」也一起超时。用户口径：

- 「为什么只是改一下数据库里的 ID 要这么久，不应该瞬间完成吗」
- 「不管电源状态怎么样，同步信息只要上游产品在，应该进行」

## 前置事实（已核实，2026-10-21）

- **切换很慢且误报失败**：nginx 记 `PUT /api/v2/admin/users/1086/services/3783/meta` 两次 `499`（客户端 10s 超时先断开），而 `service_upstream_bindings` 已出现 `upstream_service_id=10308` 的新行——写库成功，失败的是回源等待。
- **回源耗时 26.2s**（生产实测 `fetchRemoteState`）：主机详情 0.9s + 电源状态 5.4s + 3 个自定义区域 HTML 页 6.7/5.0/6.4s + NAT 远程地址抓取。管理端 axios 默认超时 10s（`frontend-admin-v3/src/utils/request/index.ts:215`），且 GET 默认 `retry.count=3`。
- **自定义区域 HTML 只用于拼面板入口**（`PanelAccessExtractor::mergeHtmlSources`）：云服务器（`console_template=compute`）拿到的是快照/备份/安全组页，拼不出面板，却要付 18s；控制台 tab 的内容由 `ServiceConsoleAreaService` 独立抓取，不依赖这份载荷。
- **电源状态失败会打断整条同步**：`ServiceStatusSyncService` 与 ZJMF 插件 `ZjmfStatusService` 在运行状态读取失败时抛异常，生产 `3711/3790/3897/3900/3912` 等实例的 IP、到期时间、运行状态因此长期不再更新。

## 范围与验收

- [x] 切换上游绑定改为「本地写立即返回」：事务提交 + 绑定行同步后读本地快照返回，上游回源交给后台同步任务（生产实测 `updateServiceMeta` 434ms）。
- [x] 回源提速：云服务器不抓自定义区域 HTML、非 NAT 控制台不抓 NAT 远程地址（生产实测 26.2s → 6.2s，两个请求都回到 10s 超时之内）。
- [x] 管理端这几个慢请求单独放宽到 60s 并关掉 GET 自动重试；上游过慢时给中性提示「同步请求已提交，后台正在同步，请稍后刷新查看」，不再弹红色失败。
- [x] 状态同步：电源/运行状态读取失败降级为「仅同步实例详情」，失败原因写进 `status_sync_error` 与告警日志；上游实例真的读不到（已删除/不存在）仍然判失败。
- [x] 切换上游主机后收敛 `provision_data.upstream_host_ids`，不再继续显示切换前的旧主机。
- [x] 回归：新增 4 个纯单元测试文件（15 例）、3 条管理端 e2e；`pnpm run docs:check` 与管理端类型检查通过；生产部署后逐项复验。

## 非目标

- 不改 `upstream_host_id` / `downstream_host_id` 的既有语义（后者本轮不动，只在切换时不动它）。
- 不放宽管理端全局 axios 超时，只给上游同步类请求单独设置。
- 不动状态同步里「实例详情读不到即判失败」这条真实故障路径。

## 决策日志

- **切换绑定不在请求内等上游**：本地写与远端回源解耦，远端交给已有的 `ServiceConsoleSyncJob`（10s 节流），后台同步完成后仍走既有的「变更标记 → 前端自动刷新」链路。
- **按商品类型收窄回源范围，而不是给所有实例提速**：面板型商品（CDN/虚拟主机/端口映射）继续抓自定义区域 HTML，云服务器跳过；NAT 控制台继续抓 NAT 远程地址，其余跳过。跳过条件放在 `ServiceDetailService`，唯一真源。
- **电源状态降级放在「运行状态读取」这一层，不放在「整条同步」这一层**：实例详情读不到仍判失败，避免把真实故障吞掉。
- **前端不给慢接口开自动重试**：重试会重复触发上游同步并把等待放大到数倍，60s 超时叠加 3 次重试比现状更糟。

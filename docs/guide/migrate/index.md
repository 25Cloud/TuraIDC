# 数据迁移

把既有业务数据搬进 TuraIDC：从智简魔方财务系统迁移存量客户、产品、订单与上游绑定，或把旧 IDC 系统的异构数据映射过来。

## 1. 迁移路径

| 来源                                                     | 适用场景                                                                   |
| -------------------------------------------------------- | -------------------------------------------------------------------------- |
| [从智简魔方财务系统迁移](zjmf-finance.md)                | 老站跑的是智简魔方财务（ZJMF），要把用户、产品、订单、上游与实名整体搬过来 |
| [魔方财务迁移（实验工具）](zjmf-finance-experimental.md) | `shd_` 前缀数据的实验性迁移工具，已被正式指南取代，仅供追溯                |
| [本地 IDC 数据迁移](local-idc.md)                        | 旧 IDC 系统的表结构与 TuraIDC 不同，需要做异构字段映射与受控导入           |

## 2. 迁移前必须做的事

1. **完整备份源站与目标站的数据库**，并确认备份可恢复——迁移过程中任何一步失败都靠它回退。
2. **在非生产环境先跑一遍全流程**，包含导入后的结构与数据验收，不要拿生产库试。
3. **记录映射决策**：哪些字段对齐、哪些字段丢弃、哪些需要人工判定归属，写成表格留档。
4. **安排好停机窗口**：迁移期间不要让用户下单或支付，避免新旧数据交叉写入。
5. **迁移后逐项验收**：用户能登录、余额与订单金额对得上、实例能续费、上游绑定可用。

## 3. 迁移后复核

- 用户数与订单数在源站与目标站一致，或差异有明确解释。
- 余额、发票与账务流水能对上；不一致的按[财务与账单](../operate/finance.md)排查。
- 至少抽 3 个真实实例验证续费与上游操作可用。
- 迁移完成后仍保留源站只读一段时间，确认无遗漏再下线。

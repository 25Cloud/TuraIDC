# 部署安装

把 TuraIDC 部署到生产环境。先按下表选择与当前服务器和运维流程匹配的方式，完成部署后再照[部署与调度](scheduling.md)配置计划任务、队列与就绪检查——漏掉这一步，自动开通、自动续费与通知都不会执行。

## 1. 选哪种方式

| 方式                                        | 适用场景                                                   |
| ------------------------------------------- | ---------------------------------------------------------- |
| [通用部署](generic.md)                      | 不绑定面板或容器：按环境要求手工完成后端、前端与进程守护   |
| [宝塔面板部署](bt-panel.md)                 | 服务器上已有宝塔面板管理 PHP、Nginx 与计划任务             |
| [裸机源码部署](bare-metal.md)               | 无面板、无容器，以 nginx + PHP-FPM + systemd + cron 原生运行 |
| [Docker 与 1Panel](docker-1panel.md)        | Docker Compose 部署，或用 1Panel 统一管理容器               |

## 2. 部署后必做

1. **确认依赖服务**：应用、数据库与 Redis 都正常运行；Redis 在生产是必需的（分布式锁与缓存）。
2. **配好调度**：按[部署与调度](scheduling.md)设置每分钟一次的计划任务、队列组与心跳探针，并配置 VNC Relay 常驻进程。
3. **自检环境**：在 `backend/` 下执行 `php artisan app:doctor`，确认 PHP 版本、必需扩展与禁用函数都满足要求。
4. **跑一次真实链路**：用一笔小额订单走通「下单 → 支付 → 自动开通 → 通知」。

## 3. 相关约束

- 数据库最低兼容 MySQL 5.7.44，推荐 8.x；SQL 必须同时兼容两个版本。
- 生产不使用 `php artisan serve`，后端入口走 PHP-FPM。
- 版本升级只跑新增迁移，绝不删表、删列、删索引。

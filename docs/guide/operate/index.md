# 日常运营

系统上线之后的日常经营操作：上架商品、处理订单与开通、对账与退款、维护用户与分销关系、回复工单、管理通知。

## 2. 每日建议复核

1. **未支付订单**：看到期未付的订单量与金额，判断是否需要催付。
2. **开通失败队列**：支付成功但未开通的实例必须当天处理，用户已付款。
3. **工单与超时**：有未回复工单时先响应，避免触发超时自动关闭。
4. **账务一致性**：核对余额变动与账务流水是否对得上，有异常按[财务与账单](finance.md)排查。
5. **通知失败**：邮件或短信连续失败通常意味着通道配置或配额出问题，见[通知与站内信](notifications.md)。

## 3. 不可逾越的操作边界

- 支付记录只改状态，**不物理删除**；任何资金相关的调整都要留下可追溯的记录。
- 订单、续费金额由服务端按规则重算，客户端参数不能作为金额依据——手工改单时同样遵守这个口径。
- 已购用户的实例不因商品下架而失效；下架只影响新购。
- 涉及删除表的操作一律不做，升级与迁移路径依赖表结构稳定。

# 维护与升级

把站点长期跑下去需要的操作：升级到新版本、备份与恢复、日志归档与数据库维护，以及前端站点的 Nginx 缓存与伪静态规则。

## 1. 维护事项

| 事项                                    | 什么时候做                                   |
| --------------------------------------- | -------------------------------------------- |
| [版本升级](upgrade.md)                  | 有新版本发布、需要修复线上问题时             |
| [备份与恢复](backup.md)                 | 上线前配置一次，之后按周期执行并定期演练恢复 |
| [日志归档与 MySQL 维护](log-archive.md) | 日志表膨胀、磁盘吃紧、需要冷热数据分离时     |
| [前端站点 Nginx 规则](nginx-rules.md)   | 部署三端前端、配置伪静态与缓存策略时         |

## 2. 维护原则

- **迁移只新增**：升级只跑新增的数据库迁移，绝不删表、删列、删索引——存量升级与魔方财务搬迁都依赖表结构稳定。
- **先备份再动手**：任何升级、数据修复与配置变更前先做一次可验证的备份，见[备份与恢复](backup.md)。
- **失败可回退**：升级前记录当前版本与前端产物位置，出问题能退回上一份产物与代码。
- **保持调度在跑**：升级期间计划任务、队列与心跳会中断，完成后必须确认它们恢复运行，否则自动开通与续费会静默停摆。

## 3. 例行检查

```bash
cd backend
php artisan app:doctor          # PHP 版本、扩展、禁用函数是否仍满足要求
php artisan schedule:list       # 定时任务是否登记完整
```

磁盘与日志增长、数据库体积、备份产物是否按时生成，都建议纳入每周一次的人工复核。

# 維護與升級

把站點長期跑下去需要的操作：升級到新版本、備份與恢復、日誌歸檔與資料庫維護，以及前端站點的 Nginx 快取與偽靜態規則。

## 1. 維護事項

| 事項                                    | 什麼時候做                                   |
| --------------------------------------- | -------------------------------------------- |
| [版本升級](upgrade.md)                  | 有新版本釋出、需要修復線上問題時             |
| [備份與恢復](backup.md)                 | 上線前配置一次，之後按週期執行並定期演練恢復 |
| [日誌歸檔與 MySQL 維護](log-archive.md) | 日誌表膨脹、磁碟吃緊、需要冷熱資料分離時     |
| [前端站點 Nginx 規則](nginx-rules.md)   | 部署三端前端、配置偽靜態與快取策略時         |

## 2. 維護原則

- **遷移只新增**：升級只跑新增的資料庫遷移，絕不刪表、刪列、刪索引——存量升級與魔方財務搬遷都依賴表結構穩定。
- **先備份再動手**：任何升級、資料修復與配置變更前先做一次可驗證的備份，見[備份與恢復](backup.md)。
- **失敗可回退**：升級前記錄當前版本與前端產物位置，出問題能退回上一份產物與程式碼。
- **保持排程在跑**：升級期間計劃任務、佇列與心跳會中斷，完成後必須確認它們恢復執行，否則自動開通與續費會靜默停擺。

## 3. 例行檢查

```bash
cd backend
php artisan app:doctor          # PHP 版本、扩展、禁用函数是否仍满足要求
php artisan schedule:list       # 定时任务是否登记完整
```

磁碟與日誌增長、資料庫體積、備份產物是否按時生成，都建議納入每週一次的人工複核。

# 郵件與簡訊

郵件與簡訊都走「整合外掛」：先在外掛頁安裝並啟用一個通道外掛，再填憑據，最後開啟站點設定裡的通知總開關。三個環節少一個，對外就發不出驗證碼。本文按這個順序說明入口、欄位、留空後果與驗證方法。

## 1. 後臺入口

| 頁面                 | 路徑                                          | 許可權                                        |
| -------------------- | --------------------------------------------- | ------------------------------------------- |
| 郵件傳送（外掛列表） | 系統設定 → 整合外掛 → 郵件傳送                | 列表 `integration_plugin.view`；安裝/改配置/啟停 `integration_plugin.manage`；測試傳送 `integration_plugin.test` |
| 簡訊傳送（外掛列表） | 系統設定 → 整合外掛 → 簡訊傳送                | 同上                                        |
| 通知總開關           | 站點內容 → 站點配置 → 站點設定 → 通知總開關   | 頁面 `site.view`，寫入 `settings.manage`    |
| 郵件模板             | 站點內容 → 通知與介面 → 郵件模板              | `settings.view` / `settings.manage`         |
| 簡訊模板             | 站點內容 → 通知與介面 → 簡訊模板              | 同上                                        |
| 郵件日誌 / 簡訊日誌  | 日誌中心 → 日誌管理 → 郵件日誌 / 簡訊日誌     | `log.list`                                  |

外掛列表頁會掃描 `backend/plugins/{domain}/` 下的目錄，本地新增外掛檔案後點「掃描外掛」才會出現。安裝與啟用是兩步：點「安裝」寫入記錄，再點「啟用」啟用執行時。

「傳送測試郵件 / 傳送測試簡訊」屬於測試介面（`integration_plugin.test`），限流 10 次/分鐘——它會真實發信，只是走了直髮通道。沒有這個許可權的賬號在外掛詳情頁點測試會提示無許可權。

## 2. 一個功能域只能啟用一個外掛

`mail`、`sms` 與 `captcha`、`verification` 同屬「單啟用域」。域內已有一個啟用外掛時再去啟用第二個，會直接報「當前功能域已啟用「XXX」，請先停用後再啟用其他外掛」（錯誤碼 42200）。支付與上游不受此限制，可以並存多個。

啟用的同時會寫一條驅動繫結記錄，系統按它決定當前用哪個驅動；繫結找不到時才回退環境變數 `MAIL_DRIVER_DEFAULT`（預設 `smtp`）與 `SMS_PROVIDER_DEFAULT`（預設 `aliyun`）。所以換簡訊服務商的標準做法是：先停用舊外掛，再啟用新外掛，不需要改 `.env`。

## 3. 郵件通道

可選外掛：`smtp`（Single SMTP，生產用這個）、`multi_smtp_round_robin`（多 SMTP 輪詢）、`demo_mail`（演示，不連線真實 SMTP）。

`smtp` 外掛欄位：

| 欄位                    | 預設值 | 留空後果                                       |
| ----------------------- | ------ | ---------------------------------------------- |
| `host` SMTP 主機        | 空     | 傳送直接拋「郵件介面配置不完整」               |
| `port` SMTP 埠        | `465`  | 埠 ≤ 0 同樣報配置不完整                      |
| `username` SMTP 賬號    | 空     | 報配置不完整；同時兼作預設發件人地址           |
| `password` SMTP 密碼    | 空     | 報配置不完整（儲存後不回顯，留空儲存表示不改） |
| `from_address` 發件人地址 | 空   | 回退使用 SMTP 賬號，保持老配置行為             |
| `from_name` 發件名稱    | 空     | 回退當前站點名稱                               |
| `encryption` 加密方式   | 「自動」 | 自動時按埠推斷：465 → SSL，25 → 無，其餘 → TLS |
| `timeout_seconds` 超時秒數 | `8` | 無效值同樣按 8 秒處理                          |
| `rate_limit_enabled` 啟用電子郵件驗證碼限流 | 開 | 關閉後單 IP 不再限制驗證碼請求            |
| `ip_minute_limit` 單 IP 每分鐘上限 | `6` | 填 0 表示不限制                         |

`from_address` 與 SMTP 賬號可以不同；多數企業電子郵件要求兩者一致或已授權，不一致會被對方拒收，這屬於對端策略，系統不做校驗。

`multi_smtp_round_robin` 用「SMTP 賬號列表」（`accounts`，JSON 型別、標記為金鑰）維護多個賬號，通過賬號管理器維護，失敗後自動輪詢到下一個可用賬號，`cooldown_seconds` 預設 60 秒，即傳送失敗的賬號冷卻 60 秒後才重新參與輪詢。它的限流項與 `smtp` 相同。

郵件模板在「郵件模板」頁維護，落到 `notification_templates` 表，鍵名字首為 `email_template_subject_`、`email_template_content_`、`email_template_enabled_`。在後臺改過內容或啟用開關的模板會被標記為已個性化（`is_custom=1`），系統升級時**不會**用新版預設模板覆蓋它；沒動過的模板會隨升級重新整理。升級後覺得某封郵件樣式沒更新，先看這個模板是不是被改過。

## 4. 簡訊通道

可選外掛四個，能力並不相同：

| 外掛 slug    | 名稱             | 上游產品與介面                                    |
| ------------ | ---------------- | ------------------------------------------------- |
| `aliyun`     | 阿里雲號碼認證   | 號碼認證（PNVS）/ `SendSmsVerifyCode`，免資質，僅中國大陸號碼 |
| `aliyun_sms` | 阿里雲簡訊服務   | 簡訊服務（SMS）/ `SendSms`，V3 簽名，需資質報備與簽名、模板稽核 |
| `stay33`     | MC雲簡訊         | 按平臺 API 資訊填使用者名稱與使用者金鑰                 |
| `demo_sms`   | Demo 簡訊        | 只模擬傳送結果，用於驗證外掛流程                  |

`aliyun` 與 `aliyun_sms` 是阿里雲的兩個獨立產品，控制台、介面、套餐包、簽名與模板體系互不相通，模板不能互換。`aliyun` 的驗證碼模板由外掛按業務場景內建選擇（控制台贈送的 100001–100005），因此**沒有模板 ID 填寫項**；用錯產品會出現「扣了號碼認證套餐但簡訊服務的模板報缺引數」這類錯配。

`aliyun_sms` 欄位較多，分四組：

- 憑據：`access_key`、`secret_key`（AccessKey Secret）、`sign_name`（簡訊簽名，必須是控制台「簽名管理」中稽核通過的名稱）、`endpoint`（預設 `dysmsapi.aliyuncs.com`，僅專屬/國際站接入點才需要改）。
- 驗證碼模板：`template_code` 預設模板 ID（必填，形如 `SMS_123456789`，所有場景都回退到它）；`code_variable` 驗證碼變數名（預設 `code`，必須與模板正文的 `${...}` 佔位符一致）；`expire_variable` 有效期變數名（留空表示模板裡沒有該變數，填了但模板沒有會被阿里雲拒絕）。
- 分場景模板：`template_login`、`template_change_phone`、`template_reset_password`、`template_bind_phone`、`template_verify_bound_phone`，全部可留空，留空即沿用預設模板。只備案了一個模板時只填預設模板即可。
- 限流與高階：`rate_limit_enabled`（預設開）、`ip_minute_limit`（預設 `6`，0 表示不限）、`request_timeout`（預設 10 秒，範圍 3–30）。

`code_variable` 填錯是最常見的一類故障：阿里雲會返回「模板引數缺失」，日誌裡能看到，但簡訊就是發不出去。

`stay33` 需要 `username`、`api_key`（使用者金鑰）、`sign_name`（簽名名稱，不含外層 `【】`），傳送前需在平臺完成簽名與實名並確認賬號有額度。

## 5. 簡訊模板

「簡訊傳送」外掛裡的模板 ID 是通道側的編號；系統側每個通知場景還有自己的模板記錄，在「簡訊模板」頁維護，落到 `notification_templates` 表。對應設定鍵為 `sms_template_content_{code}`、`sms_template_provider_template_id_{code}`、`sms_template_enabled_{code}`。

`provider_template_id` 是「這個系統場景用通道的哪個模板」的對映，解析順序是：本次呼叫顯式傳入 → 模板行上存的 `provider_template_id` → 舊版驗證碼模板 ID → 回退用系統模板編號本身。所以只配 `aliyun_sms` 的預設模板、其餘留空也能跑通驗證碼；要用不同場景發不同簡訊，才需要逐個場景指定通道模板 ID。

## 6. 驗證與排障

按下面順序驗證，每一步都能定位到具體環節：

1. 外掛詳情頁點「檢測」（`health_check`）：校驗清單檔案、必需的配置項是否齊全，並例項化入口類；入口類自己實現了健康檢查時還會返回它的結果。它**不聯絡上游、不發信**，只回答「這個外掛能不能正常載入」。
2. 阿里雲簡訊服務外掛配置裡的「檢測」按鈕：一次性只讀核驗憑據、簽名與模板，並比對模板正文的變數名，不發簡訊、不計費。簽名或模板沒稽核通過會在這裡暴露。
3. 郵件外掛詳情頁「傳送測試郵件」（填收件人電子郵件，固定用賬號索引 0）或簡訊外掛詳情頁「傳送測試簡訊」（填手機號）。這一步走驅動直髮，**繞過通知總開關**；如果總開關是關的，成功提示裡會明確寫出「但站點設定中的『啟用郵件通知』當前為關閉狀態，對外仍不會發送郵件」，不要把它讀成「已經能用了」。
4. 開啟站點設定裡的 `email_enabled` / `sms_enabled`。
5. 用真實使用者走一遍註冊或找回密碼，然後到「郵件日誌」或「簡訊日誌」看記錄：日誌裡帶收件人、模板編號、通道模板 ID、狀態與錯誤資訊，失敗原因就在這裡。

```bash
# 出问题时先确认队列与调度在跑，通知类任务由心跳驱动
cd /你的项目/backend
php artisan schedule:run
```

常見故障對照：

- 測試成功但使用者收不到：通知總開關是關的，或對應模板被停用（`is_enabled` 為 0）。
- 簡訊報「模板引數缺失」：`code_variable` 與通道模板正文的變數名不一致。
- 報「簡訊驅動 [xxx] 未註冊」：啟用了外掛但沒有繫結記錄，重新停用再啟用一次。
- 郵件報「郵件介面配置不完整」：`host`、`port`、`username`、`password` 有一項為空。

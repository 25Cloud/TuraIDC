# 站點與品牌設定

站名、Logo、主題色這些三端都可見的資訊統一在管理端一個頁面維護，儲存後寫入 `settings` 表並即時下發。本文說明每一項填什麼、留空會怎樣、改完怎麼驗證。

## 1. 後臺入口

| 頁面                 | 路徑                              | 頁面許可權    | 讀寫介面許可權                             |
| -------------------- | --------------------------------- | ----------- | ---------------------------------------- |
| 站點設定（基礎資訊） | 站點內容 → 站點配置 → 站點設定    | `site.view` | 讀 `settings.view`，寫 `settings.manage` |
| 通知總開關           | 同上頁面「通知總開關」分割槽        | `site.view` | 同上                                     |
| 首頁 Banner          | 站點內容 → 站點配置 → 首頁 Banner | `site.view` | 同上（首頁裝修走自己的介面）             |

站點設定頁面的可見性看 `site.view`，但表單讀的是 `GET /api/v2/admin/settings`、寫的是 `POST /api/v2/admin/settings`，這兩個介面分別要求 `settings.view` 與 `settings.manage`。只給了 `site.view` 的賬號能進頁面、點了儲存會提示無許可權——這不是頁面故障，是許可權沒配全。系統裡定義了 `site.manage` 這個許可權常量，但當前沒有任何路由使用它（未在程式碼中確認它的用途）。

## 2. 基礎資訊欄位

配置分組是 `basic`，鍵名即下面每項的行內程式碼。

| 欄位                                         | 預設值                                | 生效範圍                               |
| -------------------------------------------- | ------------------------------------- | -------------------------------------- |
| `site_name` 站點名稱                         | `图拉云`                              | 官網、使用者控制台、管理端、郵件         |
| `browser_title` 瀏覽器標題                   | 空（回退站點名稱）                    | 官網首屏、標籤頁、分享卡片             |
| `site_logo` 站點 Logo                        | 空（回退 `/branding/logo.png`）       | 官網、控制台導航                       |
| `site_favicon` 站點 Favicon                  | 空（回退 `/branding/favicon-32.png`） | 瀏覽器標籤頁圖示                       |
| `client_console_icon` 使用者控制台圖示         | 空（回退 Favicon）                    | 控制台側邊欄、登入頁                   |
| `brand_primary_color` 品牌主色               | `#165DFF`（TDesign 品牌藍）           | 三端強調色                             |
| `brand_radius` 介面圓角                      | `6`                                   | 三端控制元件與容器圓角                     |
| `product_display_mode` 商品展示方式          | `list`（列表式）                      | 前臺商品列表預設形態（訪客可自行切換） |
| `service_phone` 官方 QQ 群                   | 空（回退文案「待補充群號」）          | 官網頁尾、控制台聯絡方式               |
| `service_email` 合作電子郵件                     | 空（該行不顯示）                      | 官網頁尾、控制台聯絡方式               |
| `service_hours` 服務時間                     | 空（該行不顯示）                      | 官網頁尾、「關於我們」頁               |
| `support_group_qr` 官方群聊二維碼            | 空                                    | 官網與控制台的聯絡入口                 |
| `support_group_link` 入群連結                | 空                                    | 同上                                   |
| `icp_record` ICP 備案號                      | 空（頁尾該行不顯示）                  | 官網頁尾                               |
| `value_added_license` 增值電信業務經營許可證 | 空                                    | 官網頁尾                               |
| `terms_url` 服務條款連結                     | 空                                    | 註冊與下單頁的服務條款入口             |
| `privacy_url` 隱私政策連結                   | 空                                    | 同上                                   |

品牌主色與圓角的取值有硬校驗，填錯不是「不好看」而是「靜默回退預設值」：

- `brand_primary_color` 只接受 `#RRGGBB` 或 `#RGB`，三位寫法會展開成六位並轉小寫。帶分號、花括號、逗號或 `url()` 的輸入會讓整條樣式規則失效甚至成為注入點，系統直接回退 `#165DFF`。管理端表單本身也有 `#(?:[0-9a-fA-F]{3}|[0-9a-fA-F]{6})` 的正則校驗，但服務端不信任前端，落庫前會再校驗一次。
- `brand_radius` 只接受 0–24 的整數畫素，超過 24 回退 `6`。專案規範是容器取該值、控制元件取一半，即預設的 6px / 3px；填成 30 這類值會看到圓角忽然變小，那是回退，不是沒儲存。
- `service_qq_group` 與 `service_phone` 是同一展示位的兩個候選鍵，取值時先看 `service_qq_group`，為空再取 `service_phone`，都為空則顯示佔位文案「待補充群號」。官網頁尾上那一行寫著「待補充群號」就說明這裡沒填。

`client_console_icon` 只在使用者控制台生效；官網頂欄與頁尾用的是站點 Logo 加站點名稱。圖片欄位接受的是媒體庫上傳後的地址，也可以直接填 `/branding/` 下的靜態檔名。

`product_display_mode` 只決定訪客**第一次**開啟選購頁看到的形態。訪客可以在選購頁右上角切換「卡片式 / 列表式」（手機端同樣有切換條），還可以在「頁面寬度」面板裡選固定寬度（1200 / 1280 / 1440 / 1600 / 1920）或撐滿螢幕；兩項偏好分別記在該瀏覽器的 `localStorage`（`turaidc:shop-display-mode`、`turaidc:shop-page-width`）裡，換瀏覽器、換裝置或清快取後回到站點預設值。想確認站點預設值實際生效，請用無痕視窗開啟選購頁，或先清掉這兩個鍵。

## 3. 通知總開關

同一頁面「通知總開關」分割槽屬於 `notification` 分組：

- `email_enabled` 啟用郵件通知，預設關閉。
- `sms_enabled` 啟用簡訊通知，預設關閉。

這兩個開關是「對外是否真的會發信」的唯一判定源。關閉時註冊驗證碼、找回密碼等對外發碼會直接返回「郵件服務暫不可用」，而管理端外掛詳情頁的「傳送測試郵件 / 傳送測試簡訊」按鈕走驅動直髮、不受總開關約束——測試成功不代表對外可用，測試結果裡會額外回傳總開關狀態並提示這一點。通道本身的配置見[郵件與簡訊](mail-and-sms.md)。

## 4. 儲存後多久生效

- 讀取介面 `GET /api/v2/site/config` 不快取，重新整理官網或控制台即可看到新站名。
- 儲存 `basic` 分組會觸發內容版本號自增，官網的 SEO 渲染結果與 sitemap 快取立即失效，不需要等 TTL 過期，也不用手動清快取。
- 瀏覽器標籤頁圖示與標題由首屏指令碼按上次訪問留下的 `localStorage` 快取先渲染一次，再被介面結果覆蓋。**同一個標籤頁裡改名不會立刻改標題**，新開標籤頁就正常。
- 官網上靜態引用的圖片（例如直接寫在 Nginx 裡的 favicon）可能被 CDN 或瀏覽器快取，這部分策略見[前端站點 Nginx 規則](../maintain/nginx-rules.md)。

## 5. 驗證

用介面確認服務端的真實取值，不要只看頁面回顯（頁面回顯帶表單本地狀態）：

```bash
curl -s https://你的官网域名/api/v2/site/config | head -c 800
```

返回裡的 `site_name`、`browser_title`、`site_logo`、`site_favicon`、`brand_primary_color`、`brand_radius` 就是三端實際使用的值。隨後逐項人工確認：

1. 新開瀏覽器標籤頁開啟官網，標籤頁標題與圖示已是新品牌。
2. 重新整理官網首頁與使用者控制台，站點名與主色已變；管理端重新整理後主色同步。
3. 官網頁尾的備案號、服務時間、合作電子郵件按填寫內容顯示，留空的整行不出現。
4. 用無痕視窗開啟選購頁，商品列表按 `product_display_mode` 的取值呈現為列表式或卡片式；普通窗口裡訪客的切換偏好會覆蓋預設值，這是預期行為。

改完沒有任何變化時，按順序排查：賬號是否有 `settings.manage`（儲存本身被拒）、`brand_primary_color` / `brand_radius` 是否被服務端校驗回退、瀏覽器是否拿著舊的標籤頁快取。

# 上游供應商對接

機器從上游開出來，前提是供應商記錄、憑據與商品繫結三樣都配好。本文說明入口、三種供應商協議怎麼選、憑據填什麼、連通性怎麼自檢，以及開通失敗時先看哪裡。

## 1. 後臺入口

| 頁面          | 路徑                                | 許可權                                                                                                  |
| ------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 上游提供商    | 產品配置 → 上游供應 → 上游提供商    | `supplier.list` / `supplier.detail`                                                                   |
| 上游開通外掛  | 系統設定 → 整合外掛 → 上游開通      | 列表 `integration_plugin.view`；安裝/啟停 `integration_plugin.manage`；測試 `integration_plugin.test` |
| 商品管理      | 產品配置 → 商品管理 → 商品管理      | `product.list` / `product.manage`                                                                     |
| 服務例項      | 服務管理 → 服務例項                 | 服務相關許可權                                                                                          |
| 上傳/清理日誌 | 日誌中心 → 日誌管理 → 上傳/清理日誌 | `log.list`                                                                                            |

`supplier.manage` 才能新增/修改/刪除供應商，`supplier.sync` 才能跑同步任務與批次對接，`supplier.secret_reveal` 才能明文檢視已儲存的憑據（10 次/分鐘限流並寫操作日誌）。

## 2. 可用的上游協議

供應商表單的欄位**由提供商型別決定**，不是每個型別都一樣。當前可選項：

| 提供商型別       | provider_key        | 憑據欄位                                                                                 | 協議說明                                                    |
| ---------------- | ------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 主機面板介面     | `hosting_panel_api` | `api_url` 介面地址、`api_username` 介面賬號、`api_key` 介面金鑰                          | 通用主機面板協議，核心內建，不需要裝外掛                    |
| ZJMF 財務介面    | `zjmf_finance_api`  | 同樣走上面三項憑據（該外掛不宣告自定義表單欄位）                                         | 對接魔方財務上游，需啟用 `zjmf_finance` 外掛                |
| 康樂虛擬主機     | `kanghostx`         | 介面地址填面板根地址，API 金鑰填 accesshash                                              | Kangle WHM API，需啟用 `kanghostx` 外掛                     |
| TuraIDC 開放介面 | `tura_open_api`     | 介面地址填上游站點根地址，API 金鑰填上游「API 金鑰」頁建立的完整金鑰（僅建立時展示一次） | 純自有協議，不走 ZJMF 相容鏈路，需啟用 `tura_open_api` 外掛 |
| Demo 上游服務    | `demo_servers`      | 無真實憑據，只模擬上游                                                                   | 僅用於驗證流程                                              |

供貨商型別下拉框的候選來自「外掛登錄檔 + 核心驅動」，未安裝的外掛不會出現在下拉里；選了卻儲存不了會報引數校驗錯誤。選不到某個型別時先去「上游開通」外掛頁安裝並啟用它。

`hosting_panel_api`（主機面板介面）是內建驅動，但下拉框走的是外掛登錄檔，需要有對應的上游外掛記錄才會出現。如果你確認程式碼裡有這個驅動、下拉里卻沒有，先在「上游開通」頁點「掃描外掛」；仍然沒有說明該驅動在當前部署裡沒有可註冊的外掛條目（具體註冊方式未在程式碼中確認）。

`zjmf_finance` 外掛的配置頁只有一個只讀的「上游標識」`zjmf_finance_api`，並明確要求供應商繫結的 `provider_key` 保持該值、不要別名為 `hosting_panel_api`——填成別名會導致走錯適配鏈路。

`tura_open_api` 要求上游金鑰具備 `products/orders/services/finance` 讀寫許可權且上游賬戶餘額充足；金鑰只在上游建立時展示一次，丟了只能重建。

## 3. 新增供應商

1. 「上游提供商」頁點「新增提供商」，先選「外掛提供商」（即上面的提供商型別）。
2. 「介面名稱」是隻在本站顯示的供應商名字。
3. 按選中的型別出現對應憑據欄位：必填項留空無法儲存；已儲存過的金鑰欄位會顯示「已配置」，編輯時留空表示**保持原值**而不是清空。
4. 「上游餘額告警」區：`low_balance_alert_enabled` 開關與 `low_balance_threshold` 閾值。閾值留空表示沿用預設值 20，**不等於**關閉提醒。
5. 儲存後供應商以啟用狀態（`status=1`）存在；用它行內的啟用/停用按鈕切換，停用不會影響已開通的服務，但新的開通不會走它。

介面地址有嚴格校驗：必須是 `http` 或 `https` 且帶主機名，**非 local 環境強制 HTTPS**，禁止帶賬號密碼，禁止 `localhost` 與 `.localhost` 結尾的域名，禁止內網與保留 IP。另外可以用 `HOSTING_PANEL_API_ALLOWED_HOSTS`（逗號分隔）把允許的域名收緊成白名單，一旦設定，不在名單內的域名會被拒。

憑據儲存的實質是 `supplier_plugin_bindings` 行：`base_url`、`account_name`、API 金鑰，加上外掛自定義的 `provider_config`。同一供應商下可能有多條繫結（例如同時對接兩個不同的上游），「批次匯入/對接」裡指定的 `supplier_id` + 來源組合就是用來區分它們的。

## 4. 商品怎麼連到上游

憑據配好不等於能賣，還要把本地商品與上游商品綁上：

- 開啟商品編輯頁，在供應商下拉里選這個供應商，再同步或選擇上游商品；選擇時會即時拉取上游商品列表，拉不到就說明憑據或網路有問題。
- 或者在「上游提供商」頁用供應商卡片上的「批次匯入/對接」：先重新整理上游商品樹，勾選要對接的遠端商品與本地的目標分類，再執行。對話方塊裡有三個選項：「預設上架」「自動開通」「同步配置項」，分別決定匯入後的商品狀態、是否走自動開通、是否把上游的配置項模板一併帶過來。
- 上游商品的配置項模板可以按單個商品檢視（卡片動作裡的 `config-template`），用於核對引數是否齊全。

批次對接需要 `supplier.sync`；沒有該許可權時按鈕點了只會提示，不會靜默失敗。

## 5. 自檢與驗證

按順序檢查，每一步都能定位到一層：

1. 上游開通外掛頁的「檢測」（`health_check`）：校驗清單與必需配置、例項化入口類，回答「外掛能不能正常載入」；不聯絡上游。
2. 上游開通外掛頁的「連線測試」：解析外掛宣告的第一個能力，驗證外掛在執行時能取到。
3. 供應商卡片上的「同步餘額」：真正請求上游並重新整理「上游餘額 / 最近更新時間」。餘額一直是 `-` 且按鈕灰著（提示「介面配置不完整，暫時無法同步餘額」），說明 `api_url`、`api_username`、`api_key` 有缺失。
4. 供應商卡片上的「批次匯入/對接」：能拉到上游商品樹，說明憑據、HTTPS、域名白名單與網路全部打通。
5. 用一筆真實小額訂單走開通，然後到「服務例項」看狀態，到「上傳/清理日誌」「工單推送日誌」看上游互動記錄。

```bash
# 后端到上游的网络连通性：上游调用不做 SSL 校验，但网络与域名白名单仍会挡住请求
curl -sS -o /dev/null -w '%{http_code}\n' --max-time 10 https://你的上游域名/
```

上面這條只是確認網路可達，真正的介面鑑權要看第 3、4 步的結果。

## 6. 排障

- **下拉里沒有想要的提供商型別**：對應外掛沒安裝或沒啟用，先去「上游開通」外掛頁處理。
- **儲存報「上游介面地址必須使用 HTTPS」**：非 local 環境強制 HTTPS，純 HTTP 上游要麼改域名證書，要麼在本地聯調環境驗證。
- **報「上游介面域名不在允許範圍內」**：`HOSTING_PANEL_API_ALLOWED_HOSTS` 設了白名單，把上游域名加進去或清空該變數。
- **餘額同步失敗**：先看是網路、域名白名單還是憑據問題——錯誤資訊由 `ProviderErrorMapper` 統一成中文，會寫明是「介面暫時不可用」還是業務錯誤。
- **訂單支付了但機器沒開出來**：新購與續費在支付回撥裡同步履約，同步失敗才回退 `provision` 佇列由每分鐘心跳重試。先看服務例項的最近一次開通嘗試記錄，再看佇列是否在跑（見[部署與排程](../deploy/scheduling.md)）。
- **供應商停用後老服務受影響嗎**：停用隻影響後續開通路由，已開通服務仍可管理；但狀態同步類定時任務不會再從它拉資料。

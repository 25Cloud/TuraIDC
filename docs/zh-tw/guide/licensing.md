# 開源與商業許可

TuraIDC 採用 **AGPL-3.0-or-later 與商業許可的雙許可模式**：預設免費開源，不願承擔開源義務的組織可以購買商業授權後閉源使用。

本文面向**部署並運營 TuraIDC 的站長與企業技術負責人**，講清兩件事：免費路徑下你必須履行哪些義務、什麼情況下需要買商業許可、以及如何取得原始碼與授權。

> 本文是工程側整理的合規要點，**不構成法律意見**；正式條款以 [AGPL-3.0-or-later 全文](https://github.com/25Cloud/TuraIDC/blob/main/LICENSE)、[商業許可草案](https://github.com/25Cloud/TuraIDC/blob/main/LICENSE-COMMERCIAL.md) 與雙方簽署的授權檔案為準。有爭議場景請諮詢法務。

## 1. 兩條路徑一眼看懂

|              | **AGPL-3.0-or-later（預設，免費）**            | **商業許可證（200 元/年）**                        |
| ------------ | ---------------------------------------------- | -------------------------------------------------- |
| 費用         | 免費                                           | 200 元/年，按「每個組織每個生產部署」計（可協商）  |
| 能否閉源     | **不能**：修改後對外提供服務必須公開對應原始碼   | **可以**：授權範圍內閉源使用、修改後不公開         |
| 網路服務義務 | 觸發 AGPL 第 13 條：向用戶提供完整對應原始碼     | **免除**第 13 條                                   |
| 再分發       | 必須整體按 AGPL 分發，保留許可證與宣告         | 不得轉售、白牌、再分發原始碼                         |
| 適合誰       | 能接受完全開源、願意回饋社群的個人/組織/小企業 | 敏感企業：不能公開原始碼、需私有化交付、閉源二次開發 |

**商業許可不是「付費解鎖功能」**：付費只解決「合法閉源」這一件事，不解鎖額外功能、不做功能閹割。（商業版必須滿足 `CLA.md`「商業版本構建規則」的授權鏈要求；在歷史貢獻者全部完成補籤之前，商業版與 AGPL 版的程式碼基線可能存在差異，差異只來自授權邊界，具體以訂單列明為準。）

## 2. AGPL 免費路徑：你擁有的權利

在遵守 AGPL 的前提下，你可以：

- 免費下載、部署、用於商業經營（包括對外賣商品/服務）；
- 修改原始碼、二次開發、開發自己的外掛與主題；
- 複製與分發本專案（含修改版），但必須遵守 AGPL。

**AGPL 保護的是使用者獲得原始碼的自由，不限制你用它賺錢。** 賣商品、收服務費都沒問題，問題只出在「改了卻不開源」或「閉源分發」。

## 3. AGPL 免費路徑：強制義務（必須做）

### 3.1 改了就得上線開源（第 13 條）

AGPL 第 13 條要求：如果你修改了本專案，並通過網路讓使用者使用這個修改版，就必須向這些使用者提供**完整的對應原始碼**（含你自己的改動）。

- 不能只部署不開源；
- 不能用「內部使用」「私有化交付」「SaaS 不賣軟體」繞過；
- 「對應原始碼」包括你修改過的檔案，以及生成、安裝、執行該版本所需的指令碼與配置（前端構建產物要能對應到原始碼）。

### 3.2 不得把本專案改成閉源產品再分發

- 二次開發後的對外服務仍受 AGPL 約束；
- 對外分發（發給客戶、客戶部署、映象/安裝包）必須整體按 AGPL 授權，接收者同樣獲得 AGPL 權利；
- 想閉源商用，只能另行取得[商業許可](https://github.com/25Cloud/TuraIDC/blob/main/LICENSE-COMMERCIAL.md)，**不能自行去掉許可證與版權宣告**。

### 3.3 保留署名、許可證與倉庫連結

- 不得刪除 `LICENSE`、原始碼檔案頭版權宣告、前端頁尾/側欄的版權與倉庫連結；
- 不得把 TuraIDC 品牌包裝成「自研產品」對外宣傳（商業許可也不含商標授權）；
- 修改版應在顯著位置說明「基於 TuraIDC 修改」，並保留原專案倉庫地址。

### 3.4 分發時附帶許可證與原始碼獲取方式

向他人分發（含私有化交付）時，至少要同時提供：`LICENSE` 全文、版權宣告、以及獲取對應原始碼的途徑。

### 3.5 依賴許可也要相容

引入新依賴前確認其許可證與 AGPL 相容：

- 一般可行：MIT、BSD、Apache-2.0、ISC、MPL-2.0（MPL 需保留檔案級開源）、GPL-3.0（與 AGPL 相容）；
- 需要評估：GPL-2.0-only（與 AGPL 不相容）、帶商用限制、專有元件、SSPL 等；
- 不要引入要求「禁止商用」「必須授權付費」的依賴，那會讓你的整體分發出問題。

## 4. 第 13 條怎麼落地（站長實操）

### 4.1 部署的是未修改的官方版本

**最省事、也最常見的合規方式**：不需要自己搭原始碼站，只要在站點上保留到官方倉庫的可見入口即可——官網頁尾「開源倉庫」與「開源版本」頁面就是為此設計的。同時保留版權宣告與 `LICENSE` 連結。

> 注意：如果只是改了配置、Logo、商品資料、主題色（後臺可配置項），一般不算修改程式程式碼；但如果你改了模板/元件/樣式檔案，就屬於修改，見 4.2。

### 4.2 部署的是修改過的版本

必須在站點上向用戶提供**與實際執行版本對應的完整原始碼**，推薦任選一種：

1. **公開倉庫**：把修改版釋出到公開倉庫（建議 Fork 官方倉庫並保留 LICENSE 與版權宣告），在官網頁尾/關於頁放倉庫連結；
2. **原始碼包下載**：在站點提供與線上版本號對應的原始碼包（含構建指令碼、前端原始碼、部署配置）；
3. **書面提供方式**：明確告知使用者如何獲取原始碼（如郵件申請、工單），並保證按 AGPL 要求及時提供。

> 只要線上跑的是修改版，就必須提供對應原始碼；「原始碼在另一個分支/以後釋出」不滿足要求。

### 4.3 建議的合規資訊位置

- 官網頁尾：「開源倉庫」「開源版本」入口（本專案官網已內建）；
- 關於/頁尾版權區：`LICENSE` 連結、版權宣告、「基於 TuraIDC 修改」說明（如適用）；
- 如為商業許可部署：保留授權憑證備查，避免對外誤稱「自研」。

## 5. 商業許可：適合誰、給你什麼

### 5.1 適用場景

- **敏感行業**：政企、金融、醫療、教育等不允許公開原始碼或需通過安全合規審查的客戶；
- **私有化交付**：給客戶部署但不能把原始碼交給客戶/公眾；
- **閉源二次開發**：基於本專案做定製功能，不願公開自有改動；
- **內部合規要求**：公司政策禁止使用 AGPL 軟體對外提供服務。

如果以上都不成立，用 AGPL 免費版即可，**無需購買**。

### 5.2 價格與口徑

- **200 元/年**；
- 按**每個組織、每個生產部署**計；
- 多部署、集團多主體、OEM/白牌、SaaS 對外銷售等可協商，教育/非營利可申請減免；
- 最終價格與授權數量以雙方簽署的訂單為準（詳見[商業許可草案](https://github.com/25Cloud/TuraIDC/blob/main/LICENSE-COMMERCIAL.md)）。

### 5.3 授予的權利

- 閉源部署與執行，**免除 AGPL 第 13 條**網路原始碼提供義務；
- 修改原始碼、二次開發後不公開；
- 在授權數量內私有化交付給自身客戶。

### 5.4 明確不包含

- **不含商標授權**：不能用 TuraIDC 名稱/Logo 宣傳，不能暗示官方合作；
- **不得轉售/白牌**：不能把軟體本身作為獨立商品、SaaS 轉售、模板、映象或白牌產品賣；
- **不得再分發原始碼**：不能以非 AGPL 條款把原始碼給第三方（需為其單獨取得授權）。

## 6. 如何獲取原始碼

TuraIDC 是完整開源專案，任何人不購買商業許可也可以直接拿到全部原始碼：

| 方式           | 地址                                                                |
| -------------- | ------------------------------------------------------------------- |
| GitHub 倉庫    | <https://github.com/25Cloud/TuraIDC>                                |
| 克隆           | `git clone https://github.com/25Cloud/TuraIDC.git`                  |
| Release 原始碼包 | <https://github.com/25Cloud/TuraIDC/releases>（每個版本附原始碼歸檔） |
| 官網開源頁     | 站點 `/open-source` 頁面（含上述入口與部署文件連結）                |

拉到原始碼後按[部署安裝](deploy/index.md)或[通用部署指南](deploy/generic.md)部署；升級見[版本升級](maintain/upgrade.md)。

## 7. 如何取得商業授權

當前走人工流程（正式售賣渠道待定）：

1. 在 <https://github.com/25Cloud/TuraIDC/issues> 新建議題，標題註明「商業授權申請」，說明組織名稱、部署數量、是否閉源/私有化交付；
2. 或發郵件至 `contact@turaidc.com`；
3. 專案方回覆報價與訂單，確認後簽署並付款；
4. 取得授權憑證（編號、有效期、部署數量），留存備查。

## 9. 常見問題

**Q：我只是部署本站賣雲伺服器，需要付費嗎？**
A：不需要。按 AGPL 免費使用即可；只要不閉源分發、修改後向用戶提供原始碼，就符合要求。注意分界線：**不修改程式**（只改站點配置、Logo、商品資料）並用自己的品牌對外服務，不觸發第 13 條；**修改了程式**再通過網路對外提供服務，就必須向這些使用者提供對應原始碼（或購買商業許可閉源使用）。

**Q：我不改程式碼，只改後臺配置和 Logo，要開源嗎？**
A：後臺可配置項（站點名、Logo、主題色、商品資料）不算修改程式程式碼，不需要開源自己的業務資料；但保留版權宣告與官方倉庫入口。若修改了模板/元件原始碼，則屬於修改。

**Q：客戶要求私有化部署且不能給原始碼怎麼辦？**
A：這是典型商業許可場景。要麼購買商業許可（按部署數計），要麼按 AGPL 向客戶提供原始碼。

**Q：商業許可到期不續費會怎樣？**
A：到期後有 30 日寬限期，寬限期內繼續有效；寬限期滿未續費則授權終止，此後不能繼續閉源使用，需續費或另行取得 AGPL 許可（商業許可不會自動變成 AGPL 許可）。

**Q：專案方會把開源版收回、改成閉源嗎？**
A：不會。已按 AGPL 釋出的版本不會被回收；商業許可只對取得授權的部署生效。

**Q：二次開發的外掛必須開源嗎？**
A：取決於外掛與主程式的關係。若外掛與主程式緊密結合、構成衍生作品，按 AGPL 處理；若通過獨立程序/標準介面呼叫，邊界需結合具體實現判斷，建議諮詢法務。

**Q：我開源了自己的修改，是否還要買商業許可？**
A：不需要，按 AGPL 合規使用即可。

# 資料遷移

把既有業務資料搬進 TuraIDC：從智簡魔方財務系統遷移存量客戶、產品、訂單與上游繫結，或把舊 IDC 系統的異構資料對映過來。

## 1. 遷移路徑

| 來源                                                     | 適用場景                                                                   |
| -------------------------------------------------------- | -------------------------------------------------------------------------- |
| [從智簡魔方財務系統遷移](zjmf-finance.md)                | 老站跑的是智簡魔方財務（ZJMF），要把使用者、產品、訂單、上游與實名整體搬過來 |
| [魔方財務遷移（實驗工具）](zjmf-finance-experimental.md) | `shd_` 字首資料的實驗性遷移工具，已被正式指南取代，僅供追溯                |
| [本地 IDC 資料遷移](local-idc.md)                        | 舊 IDC 系統的表結構與 TuraIDC 不同，需要做異構欄位對映與受控匯入           |

## 2. 遷移前必須做的事

1. **完整備份源站與目標站的資料庫**，並確認備份可恢復——遷移過程中任何一步失敗都靠它回退。
2. **在非生產環境先跑一遍全流程**，包含匯入後的結構與資料驗收，不要拿生產庫試。
3. **記錄對映決策**：哪些欄位對齊、哪些欄位丟棄、哪些需要人工判定歸屬，寫成表格留檔。
4. **安排好停機視窗**：遷移期間不要讓使用者下單或支付，避免新舊資料交叉寫入。
5. **遷移後逐項驗收**：使用者能登入、餘額與訂單金額對得上、例項能續費、上游繫結可用。

## 3. 遷移後複核

- 使用者數與訂單數在源站與目標站一致，或差異有明確解釋。
- 餘額、發票與賬務流水能對上；不一致的按[財務與賬單](../operate/finance.md)排查。
- 至少抽 3 個真實例項驗證續費與上游操作可用。
- 遷移完成後仍保留源站只讀一段時間，確認無遺漏再下線。

## 一、客户续费报「当前续费周期已完成，请勿重复续费」

**反馈**：2026-09-27 09:53 客户续费 `ser677108569190`（service_id=3363）失败，
提示「当前续费周期已完成，请勿重复续费」。

**根因**：`ServiceRenewService::assertNoFulfilledRenewForCycle()` 的判据写错。
原口径是「服务未过期 + 最近一次已履约的同周期续费发生在**一个周期自然月内**」即拦截：

```php
if ($fulfilledAt !== null && Carbon::parse($fulfilledAt)->gte(now()->subMonths($months))) {
    throw new BusinessException('当前续费周期已完成，请勿重复续费');
}
```

该守卫本意是防「自动续费已扣款 + 用户又手动续费」对**同一周期**双扣，但它把
「同一周期」等价成了「上一笔支付距今不到 N 个月」。**对月付而言，这个窗口恰好等于
正常续费节奏本身**，于是任何一次正常月付续费都会被拦。

线上真实数据（`ser677108569190`）：

| 项                         | 值                                         |
| -------------------------- | ------------------------------------------ |
| 上次已履约月付续费支付时间 | 2026-09-03 16:22:32                        |
| 服务到期时间               | 2026-10-04 16:47:41                        |
| 旧口径判定                 | `09-03 >= now − 1 月(08-27)` → **拦截** ❌ |

这笔续费已完整体现为 09-04 → 10-04 的有效期，客户现在要买的是**下一周期**
（10-04 → 11-04），且正处于到期前 7 天提醒窗口内——完全合法的续费却被拒。

**连带影响**：自动续费在到期前 3 天扣款（`auto_renew_days_before=3`）。对月付服务，
上一笔续费必然落在「一个月内」，因此该守卫会**静默拦掉几乎所有月付服务的自动续费**。
（2026-08-13 同周期双扣拦截上线时未覆盖到这一点。）

**修复**（[ServiceRenewService.php](../../../backend/app/Services/Provisioning/ServiceRenewService.php#L1416-L1462)）：
把判据从「支付时间是否落在某个自然月内」改为「已履约账单实际覆盖到哪个到期点」——
以支付时间按同一周期推进得到覆盖到期点，复用 `BillingCycle::advance()`
（与续费后写回 `expires_at` 的口径一致）：

- 覆盖到期点**晚于**当前 `expires_at` → 这笔已收款尚未反映到有效期
  （自动续费已扣款但履约 in-flight，用户此时再续费才是对同一周期二次收费）→ **拦截**；
- 覆盖到期点已落在当前到期时间之内 → 上一笔已完整体现，用户买的是下一周期
  （含提前续多期）→ **放行**；
- 服务已过期（属恢复动作）、未知周期、一次性/免费周期 → 一如既往不拦截。

**验证**（本机无 `idc_test` 库权限、无 PHPUnit 环境，改用只读方式对线上真实数据
直接反射调用该私有方法，逐分支实测）：

| 场景                                                                         | 旧口径  | 新口径        |
| ---------------------------------------------------------------------------- | ------- | ------------- |
| 线上 `ser677108569190`（续费已体现到有效期，买下一周期）                     | 拦截 ❌ | **放行** ✅   |
| 既有回归用例 `create_renew_invoice_blocks_when_same_cycle_already_fulfilled` | 拦截    | **仍拦截** ✅ |
| 真重复场景（已扣款但未延期，expires_at 未推进）                              | 拦截    | **仍拦截** ✅ |
| 服务已过期（恢复动作）                                                       | 放行    | **仍放行** ✅ |

**回归测试**：新增
`create_renew_invoice_allows_next_cycle_when_last_cycle_is_already_reflected_in_expiry`
（[ServiceRenewInvoiceOnlyIdempotencyTest.php](../../../backend/tests/Feature/ServiceRenewInvoiceOnlyIdempotencyTest.php#L617-L673)），
按线上形态构造「上月续费已履约 + 到期日已推进到下一周期」，断言必须建出新的未付续费账单、
且不得复用/拦截。

（09:56–10:01），最终在 **10:48 由管理员软删除了该服务**（同一时段该用户另有
5 个服务被一并删除，疑似人工清理）：

```

```

`services` 表带软删除，`findUserService()` 走 `findOrFail`，因此**该服务当前
处于「删不回来就续不了」的状态**（会 404）。本次代码修复只解决了「周期已完成」
这条拦截，**没有改动任何生产数据**；是否恢复 `services.id=3363` 需业务方决策。

恢复命令（待确认后执行）：


## 一、手机端完全用不了 VNC（核心）

**现象**：手机上打开 VNC 面板，控制栏是左侧竖条、5 个按钮竖排，遮挡大半屏幕；且没有任何键盘入口。

**根因**：`vnc.html` 的窄屏断点只是把按钮从 40px 缩到 34px、拉手收窄，布局方向仍是「左侧竖条」，
没有为触屏重排；同时页面上根本不存在软键盘相关控件。

**修复**（`frontend-user-v4-console/public/vnc/vnc.html`）：

- 窄屏/触屏下控制栏由左侧竖条改为**底部横条**：`#noVNC_control_bar_anchor` 改 `bottom:0`、
  宽度铺满，控制栏用 `translateY` 滑动；拉手移到控制栏上沿居中，箭头改为上下方向。
- 按钮横排（`flex-direction: row` + `flex-wrap`），触屏点击区放大到 46×46，logo 隐藏腾出高度。
- 全面接入 `env(safe-area-inset-*)`：状态条、控制栏、剪贴板面板、错误弹窗都避开刘海与手势条。
- 剪贴板面板改为底部弹出铺满宽度；`textarea` 字号提到 16px，规避 iOS 聚焦自动放大页面。
- 新增 380px 超小屏、横屏矮屏（`max-height:480px` + `pointer:coarse`）两个断点。

**回归**：真实实例 390×844 视口实测——底部横条生效（`anchor.bottom=0px`）、按钮横排、
键盘键 46×46、logo 隐藏，VNC 正常连接并渲染出真实桌面（canvas 1280×1024、59 种颜色）。

## 二、新增「键盘」按钮（移动端软键盘输入）

**根因**：移动端没有物理键盘，noVNC 的原生 `Keyboard` 依赖 canvas 焦点接收 `keydown`，
手机上无法唤起系统软键盘。

**修复**：

- 控制栏新增 `#btn_keyboard` 按钮 + 隐藏输入代理 `#noVNC_kbd_proxy`（1×1、`opacity:0`，
  **不能用 `display:none`/`visibility:hidden`**，否则移动端不会唤起软键盘）。
- 触屏点按 → 聚焦代理唤起系统软键盘；桌面端 → 退化为 `rfb.focus()` 聚焦远程桌面，
  交给 noVNC 原生物理键盘。
- 输入经 `rfb.clipboardPasteFrom()` 注入远程桌面。走剪贴板通道而非 keysym 映射，
  因此**中文等非 ASCII 字符也能输入**，不依赖上游 VNC 对输入法的支持。
- `input` 与 `compositionend` 两条路径都转发；软键盘弹出时监听 `visualViewport.resize`
  重新触发 noVNC 缩放计算，避免画面错位。

**回归**：代理框可聚焦（`display:block`、`visibility:visible`、字号 16px），
`input`/`compositionend` 均触发并清空值；桌面端分支正确聚焦 canvas 而非代理框。

## 三、VNC 页面 favicon 不跟随后台设置

**根因**：`vnc.html` 是独立静态页，`<head>` 里**完全没有 favicon 声明**。
控制台的 favicon 是 Vue 侧 `updateFavicon()` 在运行期改写 DOM 实现的，影响不到这个独立页面，
所以浏览器只会去请求同源 `/favicon.ico`，与后台「站点 Favicon」无关。

**修复**：

- `<head>` 补 `rel="icon"` 占位指向 `/favicon.ico`，避免首屏 404。
- 启动时并行请求公开的站点配置接口 `/api/v2/site/config`，取 `site_favicon` 覆盖。
  按资源来源分别解析：`/uploads`、`/media` 走 API 域（复用页面已有的 `api_base` 参数），
  其余相对路径走 console 域。接口失败静默保留默认图标，不阻塞 VNC 建连。

**回归**：实测 favicon 成功同步为后台配置的 `https://api.25y.cn/media/img_195221_XMEa79JZ.png`。

## 四、灰屏（打开后什么都没有）

**现象**：VNC 页面打开后灰屏，容器里连 canvas 都没建；报错 `Connection closed (code: 1006)`。

**根因**：客户端场景公开 token 带 `single_use=true`，兑换用 `Cache::pull()`——**取一次就从 Redis 删掉**。
而 noVNC 页面在刷新、重开、多页签、多设备打开时都会再次兑换同一个 token，
于是第一个请求之后的兑换全部 404，页面表现为打开即灰屏。

**修复**（`backend/app/Services/ClientServiceConsole/ServiceVncService.php`）：

- `loadVncTokenParams()` 与 `consumeVncLaunchToken()` 去掉 `pull()`，改为 TTL 内幂等读取。
- 移除随之失效的 `single_use` 字段与 `$consumeSingleUse` 参数。
- **安全边界仍由三层承担**：600s 短有效期、Origin 白名单、relay token 独立 60s TTL。

**注意**：这是**语义变更**——公开 token 在有效期内不再是一次性的。
若后续需要严格一次性语义，应在前端首次兑换后即 `history.replaceState` 剔除 token，
而不是依赖服务端销毁缓存。

## 五、上游并发槽位限制导致「重连必失败」

**现象**：第一次连接成功，之后再连必失败，日志 `[VNC Relay] 上游连接失败 ... 上游拒绝 WebSocket 握手`。

**排查结论**（逐一排除，实测数据）：

- 上游 `mf.lstudioc.com` 本身可重复连（顺序 3 次全 101，含完整 RFB 会话）；
- 我们的 relay 经 PHP 直连可重复连（同一 relay token 连 2 次都成功）；
- `ss` 确认 relay 在客户端断开后 **4 秒内释放上游 socket，零残留**——**不是 relay 泄漏**；
- 真实原因是：**上游 VNC 网关对同一主机有并发槽位限制（实测上限 3），且槽位释放有延迟**。
  用户重连时复用同一张旧链接会被直接拒绝，而页面「重新尝试」永远撞同一张票。

**修复**（`backend/app/Console/Commands/VncRelayCommand.php`）：

- 新增 `connectUpstreamWithRetry()`：首次握手被拒时，由服务端重新申请一条上游链接并重试一次；
  若取回的上游链接没变化则直接抛原始错误，不做无意义重试。
- 新增 `ServiceVncService::refreshUpstreamVncParams()`：用 `service_id` 重新向供应商取链接。
- 新增 `ServiceDetailService::findServiceById()`：relay 无用户上下文，按 id 直取实例
  （`findUserService()` 需要 `User`，不适用）。
- `ClientServiceConsoleService` 增加对应转发方法。

**为什么放在服务端而不是浏览器**：VNC 页面是跨域 iframe，`client_token` cookie 不存在于该页
（鉴权态只在 console 域的 localStorage），调不通需要登录的续期接口——实测返回 401
`未登录或登录已过期`。

**回归**：日志确认 `[VNC] relay 重新获取上游链接` 触发且重试成功；
桌面端与手机端均稳定连接（canvas 1280×1024、60/59 种颜色）。

**运维提醒**：relay 是 systemd 常驻进程（`turaidc-vnc-relay.service`，`Restart=always`），
**每次改 relay 代码后必须重启**，否则旧代码留在内存里、改动看起来「没生效」。

## 一、现象

代理用户购买产品时折扣是对的，但**续费时会再打一次折扣**，而且每续费一轮就更便宜一轮：

以服务 `3598`（用户 1222，商品月付原价 **11.90**，代理折扣 **75%**）为例：

| 环节                    | 基准价 | 实收                        | 是否正确                     |
| ----------------------- | ------ | --------------------------- | ---------------------------- |
| 新购下单                | 11.90  | 8.92（11.90×75%）           | ✅ 正确                      |
| 2026-08-30 第一次续费   | 8.92   | 6.69（8.92×75%）            | ❌ 二次叠加                  |
| 2026-09-03 服务金额快照 | —      | `services.amount` 已成 6.69 | ❌ 被污染                    |
| 2026-10-01 再次续费     | 11.90  | 8.93                        | ✅（因事前被人工改回 11.90） |

线上随机抽样（均为代理用户，只读查询）：

| 服务 | 商品月付原价 | 代理折扣 | 当前实际会收            | 修复后应收                                    |
| ---- | ------------ | -------- | ----------------------- | --------------------------------------------- |
| 3598 | 11.90        | 75%      | 8.93 × 75% = **6.70**   | 8.92 × 75% = 6.69（历史基准已污染，见第六节） |
| 3832 | 28.00        | 70%      | 13.72 × 70% = **9.60**  | 28.00 × 70% = 19.60                           |
| 3826 | 19.90        | 85%      | 14.38 × 85% = **12.22** | 19.90 × 85% = 16.92                           |
| 3871 | 38.00        | 65%      | 24.70 × 65% = **16.06** | 38.00 × 65% = 24.70                           |
| 3882 | 45.00        | 70%      | 31.50 × 70% = **22.05** | 45.00 × 70% = 31.50                           |
| 3819 | 25.00        | 70%      | 12.25 × 70% = **8.58**  | 25.00 × 70% = 17.50                           |

代理用户服务共 **704** 个，其中 `services.amount` 与新购原价不符的 **21** 条（代理用户 18 条）。

## 二、为什么（根因）

### 2.1 既定设计：`services.amount` 必须存「**续费原价**」

续费计价的口径是「**服务基准价 → 打一次代理折扣 → 再减优惠券**」：

- [ServiceRenewService.php](../../../backend/app/Services/Provisioning/ServiceRenewService.php#L1186-L1214)
  `buildRenewConfig()` 取 `$localAmount = $cycleConfig['effective_amount']`，
  再调 `AgentDiscountService::apply($product, $user, $localAmount)`：
  `original_amount` = 折扣前基准价、`amount` = 折后价。
- [ServiceRenewService.php](../../../backend/app/Services/Provisioning/ServiceRenewService.php#L330-L335)
  把这两个值分别写进续费账单快照：`local_renew_amount`（折后）、`original_renew_amount`（折扣前基准）。
- [Service.php](../../../backend/app/Models/Service.php#L248-L251)
  `effective_amount` 的来源就是 `services.amount` 按月折算的结果
  （`$baseAmount = $defaultBaseAmount ?? $storedBaseAmount`，优先取服务金额折算价）。

也就是说：**`services.amount` 是续费基准价的唯一真源**。只要它存的是原价，续费就只打一次折扣。

### 2.2 实际写入链路全部写的是「**折后实付额**」

设计意图在代码注释与既有测试里都写明过，但四条写入路径全都反着写：

| #   | 位置                                                 | 原代码                                                        | 问题                          |
| --- | ---------------------------------------------------- | ------------------------------------------------------------- | ----------------------------- |
| 1   | `ProvisionService::processPaidInvoice()`             | `'amount' => $invoice->amount`                                | 账单实付额（已减代理折扣+券） |
| 2   | `ProvisionService::ensureLocalService()`             | `'amount' => (float) $order->amount`                          | 订单实付额（已减代理折扣+券） |
| 3   | `ServiceRenewService::finalizeRenewInvoiceSuccess()` | `'amount' => round($invoice->amount + $invoice->discount, 2)` | 加回了券，但**仍含代理折扣**  |
| 4   | `ServiceRenewService::finalizeRenewSuccess()`        | `'amount' => (float) $order->amount`                          | 订单实付额（仍含代理折扣）    |

于是形成**复利闭环**：

```
新购: services.amount = 原价 × 折扣率
续费: 基准价 = services.amount  → 再 × 折扣率  → 实收
履约: services.amount ← 实收（折后价）
下一轮: 基准价又变小了 → 再 × 折扣率 …
```

11.90 →（×75%）8.92 →（×75%）6.69 →（×75%）5.02 … 每一轮衰减 25%。

### 2.3 为什么只有代理用户中招

普通用户折扣率为 100%，`apply()` 返回原价，折后价 == 原价，写入链路"恰好"正确，
所以缺陷只在代理用户（含代理组默认折扣率与商品折扣组矩阵两条命中路径）暴露。

### 2.4 为什么现在才暴露

代理折扣体系是提交 `5420d16` 引入的。在此之前没有代理价，`services.amount` 一直是原价；
新体系上线后，新购/续费两端的写回语义没有同步改成"原价"。

## 三、修复方案

统一收口一个公共方法，明确「续费基准原价」的解析口径，四条写入路径全部改调它。

### 3.1 新增 [Service::resolveRenewBaseAmount()](../../../backend/app/Models/Service.php#L158-L195)

取值优先级：

1. 续费账单/订单快照里的 `original_renew_amount`（本次续费实际使用的基准原价）；
2. 新购定价快照的合计金额（`total_amount` / `unit_total_amount` / `base_amount`，下单时未打折原价）；
3. 兜底：实付额 + 优惠券抵扣额（老数据没有定价快照时维持原有口径，不产生回退）。

### 3.2 四条写入路径改造

| #   | 文件                                                                                                                                      | 改动                                                                  |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 1   | [ProvisionService.php](../../../backend/app/Services/Provisioning/ProvisionService.php#L137-L156) `processPaidInvoice()`                  | `amount` 与 `locked_pricing` 基准价改用 `resolveRenewBaseAmount(...)` |
| 2   | [ProvisionService.php](../../../backend/app/Services/Provisioning/ProvisionService.php#L389-L408) `ensureLocalService()`                  | 同上                                                                  |
| 3   | [ServiceRenewService.php](../../../backend/app/Services/Provisioning/ServiceRenewService.php#L1094-L1109) `finalizeRenewInvoiceSuccess()` | 写回 `$renewBaseAmount`，不再是 `amount + discount`                   |
| 4   | [ServiceRenewService.php](../../../backend/app/Services/Provisioning/ServiceRenewService.php#L1352-L1366) `finalizeRenewSuccess()`        | 写回 `$renewBaseAmount`，不再是 `order->amount`                       |

`locked_pricing` 同步用修正后的基准价重建，保证快照与 `amount` 口径一致
（即便 `locked_pricing` 已被写入错误值，[resolveRenewPricingConfig()](../../../backend/app/Models/Service.php#L244-L251)
也会优先采用由 `services.amount` 折算的默认基准价，两者互为保险）。

**不改动解析优先级之外任何逻辑**：`manual_amount` 人工改价优先级、周期折算、
成本价守卫 `assertAboveCost()`、优惠券抵扣均保持原样。

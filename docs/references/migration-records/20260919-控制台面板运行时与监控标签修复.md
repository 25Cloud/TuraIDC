## 四、面板 HTML 泄露转售 API 凭据 + 缺前端运行时 🔴

### 4.1 凭据泄露（安全）

上游渲染 `provision/custom/content` 时，把我们传入的 `now_jwt`（转售 API 凭据，约 2 小时有效）
写进片段自身的 `function ajax()`——`xhr.setRequestHeader("Authorization", "JWT eyJ…")`，
每个面板 2 处（GET / POST 分支各一）。这份 HTML 直接下发终端用户，等于交出上游账号。

**修复**：新增 `stripEmbeddedCredentials()`，在改写时删除整条 `setRequestHeader("Authorization", …)`
语句（整行 / 跨行 / 裸露 `JWT eyJ…` 字面量三重匹配），并同时应用到：

- [ServiceConsoleAreaService.php](file:///www/wwwroot/TuraIDC/backend/app/Services/ClientServiceConsole/ServiceConsoleAreaService.php)
  的 `rewriteModulePage()`（iframe 取数唯一改写点）；
- 同文件的 `proxyModulePage()`（下游中间层透传路径）。

删掉不影响功能：面板动作地址已改写为 `actions?ticket=…` 本地代理，由服务端按票据重新签名回发上游，
浏览器侧不需要该请求头。

### 4.2 缺前端运行时

上游返回的是**「半页」HTML 片段**（无 `html/head/body/doctype`），它假定渲染在魔方财务客户区页面里，
由父页面提供 jQuery / Bootstrap 4 / SweetAlert2。我们的 iframe 复不到父页面全局变量，
于是刷 `jQuery is not defined` / `$ is not defined`，按钮与弹窗全部失效。

**修复**：新增 `wrapInRuntimeDocument()`，把片段包成完整文档并把运行时脚本注入 `<head>`
（必须先于片段内联脚本解析）；`backend/public/vendor/console-panel/` 内置 4 个静态资产：

| 文件 | 版本 |
| --- | --- |
| `jquery.min.js` | 3.6.0 |
| `bootstrap.min.css` | 4.5.2 |
| `bootstrap.bundle.min.js` | 4.5.2（含 Popper） |
| `sweetalert2.all.min.js` | 11.26.25 |

**兼容垫片**：SweetAlert2 v11 已不收旧版 `type:` 参数（只 `console.warn`，图标静默丢失），
面板大量使用 `type: 'question' | 'success' | 'error'`，故注入 `sweetalertCompatShim()` 把 `type` 映射成 `icon`
（三参写法 `Swal.fire(title, msg, type)` 在 v11 里第三参本就是 `icon`，无需处理）。

**回归用例**：`ClientServiceConsoleAreaPanelRewriteTest`（2 例）。

### 4.3 面板暴露上游地址（反代 + 缓存）

**根因**：面板片段里自带的 CSS/JS 用的是上游绝对地址
（`https://ww.stay33.cn/vendor/dcimcloud/css/01setting.css` 等），直接随 iframe 下发给终端用户，
用户查看源码即可拿到上游域名/地址（含 `loading.css`、`selectFilter.js`、`04NATForward.css`）。

**修复**：新增 [ServiceConsoleAssetService.php](file:///www/wwwroot/TuraIDC/backend/app/Services/ClientServiceConsole/ServiceConsoleAssetService.php)，
把这类资源经本系统反代 + 缓存后下发：

- [ServiceConsoleAreaService.php](file:///www/wwwroot/TuraIDC/backend/app/Services/ClientServiceConsole/ServiceConsoleAreaService.php)
  新增 `proxyUpstreamAssetUrls()`：在 `rewriteModulePage()` 里把 «供应商根域名» 的绝对地址
  （含协议相对的 `//host/…`）改写成 `asset?ticket=…&path=<encoded>`，**上游域名不再出现在下发的 HTML 里**；
  URL 改写顺序为：动作地址 → 静态资源 → 剥凭据 → 注入运行时。
- 新增端点 `GET /api/v2/client/services/{service}/console-area/asset`
  （[ServiceConsoleAreaController.php](file:///www/wwwroot/TuraIDC/backend/app/Http/Controllers/Client/V2/ServiceConsoleAreaController.php#L89-L123)，
  [routes/v2-client.php](file:///www/wwwroot/TuraIDC/backend/routes/v2-client.php#L50-L51)），沿用同一套短时效票据鉴权。
- **防开放反代**：目标主机由「服务绑定的供应商」推导，调用方只能给路径；
  路径不接受协议头、`//` 开头（自带主机）、`..`、反斜杠与控制字符，且拼出的 URL 会复核主机一致（双保险）。
- **缓存**：Redis 缓存 24 小时（键 `service_console:asset:v1:{supplier}:{sha1(path)}`），
  回传 `Cache-Control: public, max-age=86400` + `X-Content-Type-Options: nosniff`；
  Content-Type 做白名单收敛（非 css/js/图片/字体一律降级 `text/plain`），避免同源下发可执行内容。
  单个资源上限 2 MB，失败不回源缓存。

**回归用例**：`ClientServiceConsoleAreaPanelRewriteTest` 新增 2 例（地址改写 + 路径校验，共 4 例）。

### 4.4 上游直接给完整文档时「一条样式都没有」（CDN 面板）

**现象**：CDN 实例（如 3806）的「管理面板」tab 完全没有样式。

**根因（两个叠加）**：
1. 该模块（key=`site`）的片段是**完整文档**（`<!DOCTYPE html>…</html>`），
   而且上游把自带的 Bootstrap `<link>` **注释掉了**：

   ```html
   <!-- <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/bootstrap@4.6.1/dist/css/bootstrap.min.css"> -->
   ```

   它同样指望「父页面」提供样式，而 iframe 里没有父页面；
2. 上一版的 `wrapInRuntimeDocument()` 遇到完整文档**直接原样返回**（怕套壳破坏结构），
   于是连我们注入的 Bootstrap 都没进去 → 零样式。

**修复**（[ServiceConsoleAreaService.php](file:///www/wwwroot/TuraIDC/backend/app/Services/ClientServiceConsole/ServiceConsoleAreaService.php)）：
新增 `injectRuntimeHead()`：完整文档不套壳，改为把运行时**插进它自己的 `<head>`**
（优先插在 `<meta charset>` 之后，既满足「Bootstrap CSS 先于片段自带 CSS」「脚本先于片段内联脚本」，
又不把 charset 挤到文档前 1KB 之外）。

**防重复**：完整文档若自带 jQuery（片段内含 `jquery` 字样），只补 Bootstrap CSS、**不再注入我们的脚本包**，
避免二次加载把前一份 jQuery 的插件注册冲掉。

**回归用例**：`ClientServiceConsoleAreaPanelRewriteTest` 新增 2 例（完整文档注入 + 自带 jQuery 时跳过脚本）。

> 说明：该面板里指向 `heicdn.cn` 的「登录面板」按钮是终端用户**自己的** CDN 账号 SSO 链接（`GuardName=client`），
> 不是我们的转售凭据，故保持原样；上游域名地址的泄漏问题在 4.3 已按同一套反代处理。

## 五、监控图表标签错误

**根因（两层，缺一不可）**：上游 `module_chart` 的条目是
`[{title:"CPU使用量",type:"cpu"},{title:"硬盘IO",type:"disk"},{title:"内存用量",type:"memory"},{title:"网卡",type:"flow"}]`

1. **插件层**：`ZjmfConsoleService::monitorChartOptions()` 读的是 `label`/`name`，**上游用的是 `title`**，
   取空后走 `monitorTypeLabel()` 兜底，而该映射只认 `bw`/`disk_io`/`memory`，`disk`/`flow` 全落到默认 `CPU`；
2. **应用层**：`normalizeMonitorDisplayLabel()` 是给**曲线名**（读取/写入/流入/流出）做的归一器，
   被顺手用在**指标名**上二次塌缩（`CPU使用量`→`cpu`、`网卡`→`宽带`）。

**表现**：四个图表标签退化为 `cpu` / `cpu` / `内存` / `cpu`。

**修复**：
- [ZjmfConsoleService.php](file:///www/wwwroot/TuraIDC/backend/plugins/servers/zjmf_finance/lib/ZjmfConsoleService.php)：
  `monitorChartOptions()` 增加读 `title`；`monitorTypeLabel()` 补齐上游真实类型 `cpu`/`disk`/`flow`，
  未知类型不再一律落到 `CPU`。
- [HandlesClientServiceConsoleMonitoring.php](file:///www/wwwroot/TuraIDC/backend/app/Services/ClientServiceConsole/Concerns/HandlesClientServiceConsoleMonitoring.php)：
  `normalizeChartOptionList()` 与 `resolveChartOptionLabel()` 不再对指标名做曲线名归一；
  新增 `monitorTypeDisplayLabel()`，仅在选项缺 `label` 时按类型兜底。

**回归用例**：`ClientServiceMonitorChartLabelTest`（4 例，含真实上游载荷）。

## 六、面板加载态「一闪就没」+ 加载圈被压成直线

### 6.1 加载态闪一下就没、内容还没出来

**根因**：`AreaTab.vue` 的加载态只在 `frameSrc` 为空（还没拿到票据）时渲染，
票据一到就换成 iframe；而 iframe 里的面板内容（含经反代的 CSS/JS）还要再走一轮，
于是**加载态一闪即隐，面板位置留一片空白**。

**修复**（[AreaTab.vue](file:///www/wwwroot/TuraIDC/frontend-user-v4-console/src/pages/client/service-console/components/tabs/AreaTab.vue)，
[styles.less](file:///www/wwwroot/TuraIDC/frontend-user-v4-console/src/pages/client/service-console/components/styles.less)）：
- 新增 `frameLoaded` 状态，用 iframe 的 `load` 事件（等其子资源也加载完才触发）作为「内容已出来」的信号；
- 加载态改成 `.area-loading` **绝对定位覆盖在 iframe 之上**，直到 `frameLoaded` 才撤掉 → 内容没出来就一直转；
- `watch(frameSrc)`：面板地址变化才压回加载态（地址不变时 iframe 不重载，避免卡住转圈）。

### 6.2 加载圈是一条直线（直角边框）

**根因**：仓库根的 [theme.css](file:///www/wwwroot/TuraIDC/theme.css#L278-L281) 有一条刻意的全局「直角」重置

```css
#app *, #app *::before, #app *::after { border-radius: 0 !important; }
```

`.area-spinner` 是靠 `border` 画的圆环，`border-radius:50%` 被它以 `!important` + id 选择器压掉，
于是只剩一条直角边（看着像一根直线）。这正是「哪里强制直角边框」的答案 —— 该文件里对
TDesign 的 loading 也做过同样的例外处理。

**修复**（[theme.css](file:///www/wwwroot/TuraIDC/theme.css#L348-L353)）：

```css
#app .service-console .area-spinner { border-radius: 50% !important; }
```

靠 `#app .service-console .area-spinner`（1,2,0）压过 `#app *`（1,0,0），与既有 t-loading 修法一致。

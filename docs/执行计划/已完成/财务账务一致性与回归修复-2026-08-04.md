# 财务账务一致性与回归修复

## 背景

修复组合支付补尾款时订单已付金额覆盖、账单明细投影缺失、管理端营业额混入非销售资金流，以及财务页面旧入口和 E2E 契约失效的问题。

不直接写入当前连接数据库的历史记录；历史账单只通过显式执行的 Artisan 命令补齐缺失明细。

关联规格：[报表中心方案](../../产品规格/进行中/报表中心方案.md)。

## 范围与验收

- [x] 组合支付后以余额结清尾款时，订单与账单的已付金额均为账单全额。
- [x] 推荐奖励、扣款与退款红字账单创建后都有 `invoice_items` 投影。
- [x] 营业额、月度趋势和商品占比不统计充值、扣款、推荐奖励，退款仍可抵减收入。
- [x] 管理端保留已记录的旧财务入口兼容重定向，财务 E2E 通过。
- [x] 历史投影补齐仅在命令携带 `--execute` 时写入，默认仅报告候选数。

## 实施步骤

1. 修复支付完成后的订单金额投影，并补充组合支付回归。
2. 统一仪表盘销售收入筛选条件并覆盖统计口径。
3. 补齐新增账单的明细投影，提供受保护的历史补齐命令。
4. 恢复管理端兼容路由并更新页面真实断言。
5. 运行受影响测试、构建、财务 E2E 与文档校验。

## 风险与回滚

- 收入口径变化会修正既有报表数值；变更仅排除已定义的非销售资金流，退款红字保留。
- 历史补齐命令不会自动执行，执行前应在目标环境先查看默认报告并备份。
- 兼容路由只重定向至现有页面，可通过移除对应路由回滚。

# Frontend Project Conventions

This document is the current specification for the three frontend applications and the `shared` package, written for the developers and agents who maintain these projects. UI frameworks must not be mixed: the admin side and the console use TDesign, while the official website uses Element Plus.

## 1. Current Frontend Projects

- `frontend-admin-v3`: admin side, Vue 3 + Vite + TypeScript + TDesign Vue Next.
- `frontend-user-v3-www`: official website and user entry, Vue 3 + Vite + Element Plus.
- `frontend-user-v4-console`: new user console, Vue 3 + Vite + TypeScript + TDesign Vue Next.
- `shared`: cross-app shared package that exports status, runtime, content, and the base components of the user console.

The legacy paths `frontend-admin`, `frontend-client`, `frontend-user-v3-console`, `frontend-www-v2`, and `frontend-console-v2` do not exist at present; do not add new references to them.

## 2. General Rules

- Use Vue 3 `script setup` + Composition API.
- Send HTTP requests through each app's existing `src/api/*` and request/runtime utilities; do not create axios instances directly.
- Read and write tokens, sessions, and site information through the existing auth/runtime/store; do not access localStorage keys directly.
- Move complex page logic down into `composables`, `domains`, `features`, `services`, or `utils` in the same directory.
- User-visible copy is written in Simplified Chinese; for error messages prefer the backend `message` and `data.errors`, and do not display English exceptions or raw third-party errors.
- Reuse `@turaidc/shared` first for status display.

## 3. `frontend-admin-v3`

Directory conventions:

- `src/main.ts`: application entry.
- `src/permission.ts`: route guard.
- `src/router/modules/`: routes split by business domain.
- `src/store/modules/`: Pinia state.
- `src/pages/`: pages, organized by business domain.
- `src/api/`: admin-side API wrappers.
- `src/style/`: Less styles and theme variables.
- `src/layouts/`: admin-side layouts.

Implementation constraints:

- Use only TDesign Vue Next for the UI.
- Use only `tdesign-icons-vue-next` for icons.
- Permission codes stay aligned with the backend `App\Support\AdminPermissions`.
- Do not add Element Plus components, styles, or icons to pages.
- Admin list pages do not use a large explanatory header card; prefer a filter area, a metric area, a toolbar, and a table card.
- Admin-side pages must not add a separate "header description card".

Verification:

```bash
cd frontend-admin-v3
pnpm run build
```

## 4. `frontend-user-v3-www`

Directory conventions:

- `src/main.js`: application entry.
- `src/app/`: core capabilities such as bootstrap, router, runtime, and stores.
- `src/api/`: site and user APIs.
- `src/pages/website/`: route entry points for official website pages; the main implementation lives in `src/views/website/`, and most files under `pages` are thin forwarding shells.
- `src/pages/common/`: common pages (currently `NotFound.vue`).
- `src/views/website/`: main implementation of official website pages (home, products, product detail, content, SEO landing pages).
- `src/domains/`: domain logic (currently only `products`).
- `src/assets/styles/`: Sass tokens, global styles, and the Element Plus style entry.

Implementation constraints:

- Use Element Plus and `@element-plus/icons-vue` for the UI.
- This application is a pure official website portal with no sign-in, sign-up, or user center; authentication and console pages live in `frontend-user-v4-console`.
- The official website home page and product pages may have a stronger visual presentation.
- Reuse `src/domains/products/*` and existing composables first for purchase, checkout, coupons, and order resumption.
- SEO is rendered dynamically by the Laravel backend (`backend/app/Services/Site/SeoRenderService.php`): head meta, JSON-LD, and body snapshots for public pages are generated by the backend from the database, and the frontend build no longer performs static prerender/sitemap/robots generation (the `scripts/generate-sitemap.mjs` and `scripts/prerender-www.mjs` files have been removed); page route meta is still used for frontend synchronization such as `document.title` at SPA runtime.
- When adding a new public page, register the path and meta in the backend `SeoRenderService::resolvePage()` at the same time, so that frontend routing and SEO rendering stay consistent.

Verification:

```bash
cd frontend-user-v3-www
pnpm run build
pnpm run test:e2e
pnpm run verify:refactor
```

For small changes, run at least `pnpm run build`; add `verify:refactor` when refactoring or touching shared logic; add `test:e2e` when changing regression-testable behavior such as the top-bar dropdown, loading states, or keyboard interaction (Playwright; the test cases stub the API themselves and do not depend on the backend or the database).

## 5. `frontend-user-v4-console`

Directory conventions:

- `src/main.ts`: application entry.
- `src/permission.ts`: route guard.
- `src/router/`: console routes.
- `src/store/`: Pinia state.
- `src/pages/client/`: console pages.
- `src/domains/`: domain logic for account, finance, services, tickets, content, marketing, and tools.
- `src/composables/`: console composable logic.
- `src/api/`: client-side API wrappers.
- `src/style/`: Less styles and TDesign tokens.

Implementation constraints:

- Use only TDesign Vue Next for the UI.
- Use only `tdesign-icons-vue-next` for icons.
- Reuse `PageScaffold`, `DataState`, `StatusTag`, and the modal/drawer/layout components from `shared/user-v3` first.
- Console pages prioritize a stable information architecture; do not use website-style hero sections, dark full-screen displays, or decoration-first layouts.
- Console business capabilities under `/client/*` align with the backend `/api/v2/client/*`.
- Finance record pages (list and detail pages for bills, orders, and top-ups) must not use statistics/metric cards.
- The page root element uses `padding: var(--td-comp-paddingTB-l) var(--td-comp-paddingLR-l)`; on mobile all pages use a uniform padding of 12px, and `paddingLR-s` or `paddingTB-m` must not be used.

Verification:

```bash
cd frontend-user-v4-console
pnpm run build
pnpm run verify:refactor
```

For small changes, run at least `pnpm run build`; add `verify:refactor` when refactoring or touching shared logic.

## 6. `shared`

Main exports:

- `@turaidc/shared/statusConfig` (the single source of truth for status labels, colors and tags)
- `@turaidc/shared/runtime`
- `@turaidc/shared/content`
- `@turaidc/shared/user-v3` (contains shared components such as `StatusTag.vue`)

Rules:

- Do not write a separate set of status copy, colors, and tags inside pages.
- Wire runtime capabilities in from `shared/runtime` or each app's existing runtime wrapper first.
- After changing `shared`, run at least:

```bash
pnpm run typecheck:shared
pnpm run test:shared
```

Then run the corresponding frontend build according to the affected scope.

## 7. Root Workspace Commands

```bash
pnpm run dev:admin-v3
pnpm run dev:user-v3-www
pnpm run dev:user-v4-console

pnpm run build:frontends
pnpm run typecheck:frontends
pnpm run test:frontends
pnpm run verify:frontends
```

The root `package.json` keeps only the workspaces that actually exist. When adding a frontend project, you must update `package.json`, `package-lock.json`, `AGENTS.md`, `docs/develop/local-development.md`, and this specification at the same time.

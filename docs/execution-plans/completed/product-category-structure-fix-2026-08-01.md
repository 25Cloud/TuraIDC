# 商品分类结构修复

## 背景

实库将 `first_product_groups`、`second_product_groups` 与 `third_product_groups` 替换为基于 `product_groups` 的兼容视图，但 `products.product_group_id` 外键和当前代码仍要求三级分类实体表。现有商品分类新增与迁移无法执行，且完整性检查发现缺少或失效的商品分类。

## 范围与验收

- [x] 生成可恢复的分类与商品关联备份，并记录写前基线。
- [x] 将三层分类恢复为可写实体表，保留现有分类和商品关联数据。
- [x] 重建 `products.product_group_id` 到三级实体表的外键。
- [x] 新建“云服务器 / 香港 / 香港3区 CN2”，并迁移商品 60，保持隐藏状态。
- [x] 分类完整性检查无阻断错误，管理端分类树和目标商品查询可用。

## 实施步骤

1. 读取实库对象、外键与分类数据，创建时间戳备份。
2. 在维护事务中替换兼容视图为三层实体表，并从 `product_groups` 迁移分层数据。
3. 重建商品分类外键，修复所有缺失或失效的商品三级归属。
4. 创建目标分类，迁移商品 60，并作数据库与接口级验证。

## 风险与回滚

该变更会替换分类视图、重建外键并更新商品分类归属。任何写前校验、备份或迁移后检查失败时停止，不删除原 `product_groups`，并使用本次备份恢复视图、外键和商品分类归属。

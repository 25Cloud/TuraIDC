# 管理员登录人机验证实施计划（2026-08-21）

## 范围与验收

- [x] 管理端提供独立的公开人机验证配置与脚本接口，不依赖用户端认证路由。
- [x] 启用人机验证插件时，管理员登录必须先通过服务端验证，缺失或无效结果不得进入密码校验。
- [x] 管理端登录页提交账号密码前弹出人机验证，并把验证结果随登录请求一次性提交。
- [x] 验证码配置返回 provider 与不含密钥的 cache_key，脚本响应禁止公共缓存，避免切换插件后命中旧脚本。
- [x] 未启用或配置不完整时保持现有登录能力，继续由登录限流与账户失败锁定兜底。
- [x] 补充后端接口回归与管理端 E2E 契约测试。
- [ ] 完成本次受影响范围验证并归档计划。

## 实施步骤

1. 复用现有验证码插件运行时和 `GeeTestService`，增加管理员公开配置、脚本端点。
2. 在管理员登录控制器进入密码认证前验证 `captcha` 载荷。
3. 管理端登录页复用 `useGeeTestCaptcha`，支持按调用场景指定配置接口。
4. 更新 API 清单、接口规范与测试指南，运行后端、管理端及文档回归。

## 风险与回滚

- 验证插件上游不可用时，已启用插件的管理员登录会按安全优先原则拒绝，避免验证链路故障时直接放行。
- 未启用或配置不完整的人机验证插件不改变原登录流程，避免新部署因未配置第三方服务被锁在后台外。
- 回滚时需要同时撤回管理端交互与后端登录校验，禁止只回滚一端造成登录不可用或验证绕过。

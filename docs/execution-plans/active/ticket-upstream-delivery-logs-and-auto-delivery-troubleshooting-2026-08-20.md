# 工单上游转发日志与自动转发排障

## 背景

工单上游转发已有当前状态字段，但前置条件未命中时静默返回，管理端无法判断工单是否提交、为何跳过或上游为何失败。本计划补齐工单级事件记录、状态摘要和管理端展示，并基于当前数据库排查自动转发未发生的原因。

## 范围与验收

- [ ] 工单转发跳过、入队、发送中、成功、失败和回复同步均可持久化查询。
- [ ] 管理端工单详情展示当前转发状态、尝试次数、上游工单号和失败原因，并可查看历史事件。
- [ ] 未配置、规则未命中、供应商开关关闭等原因不再静默。
- [ ] API 遵循统一 V2 响应和字段白名单，不泄露凭据、Token 或完整第三方响应。
- [ ] 后端定向回归测试、管理端构建通过。

## 实施步骤

1. 只读核对当前数据库、队列运行配置和调度状态。
2. 新增工单上游事件日志表、模型、资源和查询接口。
3. 在投递 Service/Job 中记录决策、状态转移和失败原因。
4. 在工单详情 API 和管理端详情页展示状态及日志。
5. 执行迁移、定向测试、前端构建和文档校验。

## 风险与回滚

- 新表和新字段均采用追加迁移，不删除或改写历史工单数据。
- 日志只保存业务标识、中文原因和必要的 HTTP 状态/耗时，不保存敏感请求内容。
- `supplier_plugin_bindings.ticket_delivery_enabled` 仅作为历史兼容字段保留，不再参与工单推送判定；工单是否推送只由工单自动转发规则决定。
- 若上游日志写入异常，不应阻断原有投递流程；事件写入采用独立安全记录并记录本地日志。
